## Откуда взяты ответы

`generate-colony-policy-responses.py` запускает неизменённый main.app через
httpx.ASGITransport и настоящий `/api/shedcolony/action`, с временной БД,
синтетическим JWT и запретом connect/getaddrinfo до импорта backend.
На Windows сначала создаётся event loop с его локальным socketpair, после чего
устанавливается запрет сети. Lifespan/боты/production не запускаются.
`colony-policy-responses.json` содержит raw HTTP envelopes, headers, call trace,
backend SHA256 и снимки состояния до/после. У 403/429 тело POST не читалось,
касса/очередь не вызывались; состояние БД одинаково. В генераторе общая схема
временной БД берётся из существующего теста Bannerlord, но вызываемый маршрут — Colony.

Обычные Colony fixtures цен, гражданина, capacity и ответов 33 игровых действий
в parity/browser вручную сконструированы. Они проверяют весь записанный трафик
и UI на этих данных; это **не** 33 ответа реальных action handlers и не
доказательство работы мода. Реальные свежие ASGI captures здесь относятся только
к внешним policy/auth отказам. Другие fixture generators имеют свои отдельные границы.

Первый ASGI запуск остановился из-за Windows socketpair до импорта backend;
первый UI fixture probe использовал ошибочно канал33 для двух других policy
каналов. Оба диагностических лога сохранены. После исправления тестовых условий
baseline повторно дал все четыре ожидаемые ошибки, а реализация — green.
