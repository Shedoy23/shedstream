# Аудит ShedLink 0.0.5 во время Twitch Review — 23.09.2026

Аудит без изменения поданного frontend, серверных файлов и игры. Проверен текущий
рабочий каталог `codex-public-release`, неизменяемый ZIP и доступный на момент
проверки production backend. Twitch Dev Console и ручной Hosted Test не открывались.

## P1 — следующий полный выкат backend из рабочего дерева откатит функции прода

На production из 335 проверенных Python-файлов backend 308 совпадают с локальными,
12 различаются, ещё 15 есть только на сервере. В частности, сервер содержит
`m129_reforge_rights.py`, `m130_clan_catalog_truth.py`, `m131_daily_claim_action.py`,
`modules/bannerlord/reforge.py`, `modules/bannerlord/heir_snapshot.py`,
`routes/event.py` и `event_manager.py`; текущий рабочий каталог их не содержит.
Серверные `routes/bannerlord.py`, `modules/bannerlord/_adapter.py`, `main.py`,
`database.py` также содержат код, отсутствующий локально.

Проверенный пример: сервер резервирует и завершает `hero.reforge_quality` в
`routes/bannerlord.py` и `database.py`; локальные файлы этих вызовов не имеют.
Поданный frontend вызывает это действие. Сервер также откатывает запись ежедневной
награды при отказе игры через `action_id`; локальный код этого не делает.

`scripts/deploy.ps1 -Backend` упаковывает весь локальный `backend` и распаковывает
его поверх production с последующим рестартом. Поэтому обычный следующий выкат
перезапишет серверные версии этих файлов. Дополнительные серверные файлы останутся,
но их маршруты/регистрация и защитная логика могут пропасть. До сведения исходников
с production полный backend-выпуск из этого дерева нельзя считать безопасным.

## P2 — ложное сообщение об успешной групповой покупке апгрейдов клана

Production `routes/bannerlord.py` при групповой покупке отвечает `success: true`,
`pending: true`, но текстом «Куплено ...». Фронт показывает этот текст сразу.
В этот момент запрос лишь поставлен в очередь; реальные динары ещё должен списать
мод, который может отказать. Одиночная покупка уже говорит «отправлена в игру».
Исправление возможно на backend без изменения ZIP.

## P3 — устаревшие указатели на кандидат

В `scripts/deploy.ps1` текст запрета выката всё ещё называет старый ZIP
`6f7e115b...`; подан `6f8e07f5...`. Сам замок работает. В
`Расширение/docs/REVIEW_SUBMISSION.md` указаны старый SHA/MD5, 24 файла вместо
27 и обещание живого канала. Поданный текст формы
`TWITCH_SUBMISSION_0.0.5_2026-09-23.txt` корректно просит согласовать игровой
сеанс, поэтому это риск при повторном использовании старого документа.

## Что проверено

- Неизменяемый ZIP: SHA-256 `6f8e07f56b7d6a0b4f628a2731d81686a47b77dd8b7cfcc912dd1f8af3f90672`, MD5 `40571fe7c7c1b54b792c816be8c37968`; `verify-candidate.py` прошёл, 27 файлов совпадают с деревом.
- Замок frontend deploy, замороженный клиент, 8 критичных backend-тестов и 7 UI/JS-тестов прошли. Два браузерных теста сначала не стартовали из-за отсутствующего локального Playwright, затем прошли с bundled `NODE_PATH`.
- Production `/health` ответил `200 {"status":"ok","db":"ok"}`; `/privacy.html` и `/terms.html` ответили 200. Сервис `twitchbot` был RUNNING. Это проверка доступности, не игровых действий.
- Установленная DLL содержит `BuyClanUpgradesHandler` и строки `hero.buy_clan_upgrades`/`hero.clan_upgrades_purchased`; игра во время проверки не была запущена. Поведение в живой кампании и Twitch Hosted Test не проверено.
- Статус In Review и совпадение MD5 в Twitch Dev Console известны из записи владельца в `RELEASE_RECORD.md`; доступ к кабинету не проверялся независимо.
