# Повторная проверка шести замечаний Claude

Владелец прислал разбор старого прогона после установки 61e4549. Проверка
текущей DLL: MD5 55B9AE163133BABA456FF5302F8E235A, совпадает с установленной
22:26 сборкой. Журнал autopilot_20260916.txt последний раз изменялся в 20:13;
он не доказывает поведение новой DLL. В этой проверке игровой код и DLL не менялись.

1. Рейд: в 61e4549 RaidSettlement исполняется штатным приказом и меню. Однако
   мод не является точной копией выбора NPC: по новому решению владельца
   готовый захват крепости приоритетнее патруля/рейда, а при нехватке ресурсов
   выбирается снабжение. Своя зачистка убежища тоже сохранена. Эти отклонения
   нельзя описывать без оговорок как «решает только игра».
2. Простой: принятый фикс Claude вызывает WatchMission каждые полсекунды в
   миссии и обновляет отметку прогресса, исключая её длительность из простоя
   карты. Это исправление кода со стендом; свежего живого подтверждения нет.
3. Лорды: в 61e4549 есть фиксированные знакомства, вызов преследуемому
   вражескому лорду, подтверждение и ответ на нападение; мирный уход отдельно.
   Неизвестные/изменённые модами ветки разговоров этим не доказаны.
4. Добыча: баланс сторон и реальный roster проверяются ДО ExecuteCompleteTranstactions.
   Это сохраняет проверку переноса; проверку снимка после callback заменили
   диагностикой. В имеющемся живом журнале только два численных расхождения:
   17:50:09: 463 → 464 (+1); 19:11:17: 513 → 515 (+2). Оба положительные и
   мелкие, но выборки недостаточно для «всегда». Конкретный изменивший предмет
   callback не установлен. Формулировка лога «обработчики закрытия изменили»
   сильнее доказательств: установлен только временной интервал изменения.
5. Убежища: при TeamAI == null код выдаёт MovementOrderCharge/FireAtWill
   непустым формациям и хранит их в _hideoutOrders. Строка «0 формаций» считает
   только _formationsGiven, то есть другой путь; она вводит в заблуждение.
   Есть отдельный незакрытый риск: после _controlGiven=true GiveControlToAi
   повторно не вызывается, поздние формации этим проходом не захватываются.
   Победа в миссии не является доказательством отсутствия этого риска.
6. Событие: Random.Next(NumOfOptions), без оценки полезности/риска. Журнал
   перечисляет варианты и результат, но не называет случайное правило в строке
   выбора. Решение о рандоме записано прежней сменой; новая установка его не
   меняла. Выбор менее выгодной опции этому алгоритму соответствует.

Следующие узкие исправления: явная диагностика правил выбора/приказов,
сценарий поздних формаций, поэлементный снимок добычи до/после закрытия для
установления источника изменения. Не вводить произвольный допуск «±2 нормально».
