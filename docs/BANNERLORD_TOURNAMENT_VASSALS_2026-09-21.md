## Турнир: причина и исправление

Сегодня мод восстановил 13 записей из сохранения, добавил banderaslv, shedoy23,
nikita__g345 до 16. В 14:38 публичный queue-usernames канала 98319857 показывал
только последних троих. Повторные заявки остальных отклонялись как «уже в очереди».
Загрузка передавала очередь только backend -> game, а game -> backend snapshot отсутствовал.

Теперь tournament.queue_snapshot передаёт упорядоченную полную очередь после загрузки,
при изменениях и каждые 10 секунд игрового Tick (включая пустую очередь).
Снимок захватывается на главном потоке; одновременно допускается один запрос.
После сетевого сбоя/непринятого handshake следующий Tick повторяет актуальное состояние.
Backend атомарно заменяет зеркало только для текущих save_id + equipment_session_id
и возрастающего queue_seq. Миграция M128 хранит последовательность.
Повторная запись подтверждает существующее членство без дубля.
Legacy joined/left не меняют зеркало после принятия snapshot текущей сессии;
старый клиент продолжает работать через отдельные события. Его start удаляет
только участников, а не всех ожидающих. Abort не очищает очередь следующего турнира.

Источник очереди теперь загруженное сохранение: прежний add-only импорт серверных
записей удалён, чтобы не возвращать уже отсутствующих участников из устаревшего зеркала.
При откате старого сохранения очередь соответствует этому сохранению.
Для будущего выката нужны backend + M128 + мод; frontend не менялся.
