# Срочная защита своих замков и городов — 21.09.2026

Решение владельца: идти защищать свои осаждённые поселения даже с 50% отряда,
пробиваться внутрь и пытаться удержать. Реализовано в `6c8d1fb`, красный стенд
`03cf867`. Основа — `7b43fac`, включая исправления двух экранов/повтора убежища
и предыдущую камеру. В игру эта новая сборка не устанавливалась.

## Почему не защищал

1. Журнал `Documents/Mount and Blade II Bannerlord/Logs/autopilot_20260921.txt`,
   строки 20985–20990, 21:36:20: лучшая штатная цель `DefendSettlement → Замок
   Пендраик = 8.740`, применимость «да». Далее `ПОХОД: снабжение/восстановление —
   боеспособны меньше 70% отряда`, выбрано `GoToSettlement → Линдорн = 1.678`,
   остались в Линдорне. Это доказанный приоритет восстановления над обороной;
   принадлежность Пендраика конкретному клану одним этим логом не установлена.
2. В OnHourlyTick найм до 90% лимита и разгрузка возвращались до сбора оценок.
   Самостоятельный поиск существовал для вражеских крепостей, для своих осад — нет.
3. Декомпиляция установленной 1.4.8: `MobileParty.ResetAllMovementParameters`
   (3896–3903) устанавливает MoveTargetPoint=Position; `SetMoveDefendSettlement`
   (4027–4033) задаёт TargetPosition, но не MoveTargetPoint. Его использует
   движение в Point-режиме (3810–3816). `SetMoveGoToSettlement` (3936–3943)
   задаёт обе точки. Прежний приказ защиты не обеспечивал движение MainParty.
4. Отдельный прежний останов: 21:18:07, строка 20436 — выключение при проверке
   улучшения бойца в Замке Флинтолг. Он уже исправлен в принятой основе 2f8fab4.
   В 21:32:48 было 230 бойцов / 229 раненых; новое правило 50% не обещает
   спасение с одним боеспособным. В 21:36:30 журнал показывает потерю последнего феода.

Декомпиляции читаются из `decompile-campaignsystem/`, в Git не добавляются.
Это структурное объяснение движения, не измерение координат после новой DLL.

## Что сделано

- Свои = города/замки из `Clan.PlayerClan.Fiefs`, не все союзники королевства.
- Для старта помощи достаточно `healthy >= ceil(total * 0.5)` в текущем отряде.
  Не нужен набор до 90% лимита, 70% здоровых или запас еды/жалования на 7 дней.
  Размер отряда может быть половиной лимита или меньше. Порог наступления
  «враг не сильнее 1.5x» не применяется к спасению своего феода.
- Свои осады ищутся независимо от предложений движка, до найма/разгрузки/похода.
  Сначала ближайшая по расстоянию; выбранная актуальная цель сохраняется, чтобы
  не метаться между осадами. Не преследуем случайных бандитов вместо неё.
- Отдых прерывается штатным выходом. Свою наступательную осаду снимаем через
  leave → break_siege_go_on, рейд — raiding_village_end. Активный бой, чужая
  армия и модальные окна не прерываются. Не ждём окончания суточного сбора армии;
  уже приглашённые отряды продолжают свой штатный подход без новых приглашений.
- Подход к крепости — GetActionForVisitingSettlement; намерение обороны сохраняется.
  Одинаковый маршрут не перевыдаётся каждый час. Снятая осада/потеря владения/
  падение готовности ниже 50% отменяет старый приказ на подходе; применяется
  существующий сторож застрявших маршрутов. Отложенный выход повторно проверяется.
- Вход: join_siege_event_break_in → break_in_menu_accept →
  break_in_debrief_continue → menu_siege_strategies. Потери рассчитывает
  штатный BreakInOutBesiegedSettlementAction; невозможные/скрытые кнопки не обходятся.
  После успешного входа потери не заставляют бежать обратно за пополнением.
- Если уже идёт наружный бой, можем присоединиться к своей стороне и продолжить
  как собственную операцию. В SallyOut гарнизон — Attacker, осаждающие — Defender
  (MapEvent.cs:816–822): нужна help_attackers. Для SiegeOutside — help_defenders.
  Условия кнопок и право присоединения остаются у игры. Штурм запускает оборону;
  раненый главный герой сохраняет общий fallback «Послать воинов».
- EncounteredBattle читается в затронутом пути только при EncounteredParty != null;
  у родного getter этого предохранителя нет. Контракт API расширен на это свойство.
- F10 не вмешивается, F12/загрузка очищают намерение защиты вместе с операциями.
