## Находки до исправления

1. **Админка / RimWorld — раздел сломан (высокий приоритет).**
   `admin.html:1286,1314` вызывает `/api/rimworld/status` и
   `/api/rimworld/events` с Basic Auth администратора. Эти маршруты в
   `rimworld.py:732,2727` требуют JWT зрителя и на production вернули 401.
   Общий `apiGet` в `admin.html:925` при 401 снова показывает экран логина,
   хотя пароль администратора верный. `/api/rimworld/all-pawns` вернул 200,
   но отдаёт **массив** (`rimworld.py:2594`), а страница читает `data.pawns`,
   поэтому число пешек и таблица всегда пусты. API уже возвращает здоровье
   в процентах, страница умножает на 100 ещё раз; `world_name` API не отдаёт.
   Нужны отдельные админские GET для статуса/каталога и единый контракт пешек.

2. **Счётчики админки и список зрителей имеют разный охват (средний приоритет).**
   `/api/admin/stats` вызывает `get_stats()` для канала по умолчанию
   (`admin.py:240`, `database.py:1387`), а `/api/admin/users` выбирает всех
   зрителей без `channel_id` (`admin.py:301`). Заголовок «Пульс платформы»
   создаёт впечатление общей статистики. Детали по одному `username` также
   не ограничены каналом (`admin.py:330`), включая инвентарь и пешку. Сейчас
   в production зрители есть только в одном канале, поэтому расхождение пока
   не проявилось на данных; при втором канале станет видимым. Нужны явный
   выбор канала и отдельная общеплатформенная сводка.

3. **Два входа в админку (средний приоритет).** Сам `/admin` защищён Basic Auth
   (`admin.py:225`), поэтому новый посетитель сначала получает браузерное
   окно HTTP Basic. После загрузки HTML страница показывает второй экран
   входа и повторно проверяет `/api/admin/stats` (`admin.html:862–900`).
   Достаточно одного понятного входа при сохранении защиты API.

4. **Статус кабинета стримера может обещать больше, чем проверяет (средний
   приоритет).** `/api/streamer/setup-status` проверяет регистрацию, одобрение,
   выбор игры и heartbeat мода (`streamer.py:430–538`), но не подтверждает
   установку или отображение Twitch Extension. При `all_good` страница пишет
   «Зрители видят расширение» (`streamer_dashboard.html:1097`). Лучше писать
   «Мод на связи, канал настроен» и отдельно показывать состояние установки
   расширения, только если есть достоверный источник.

5. **Устаревший зелёный статус при потере сессии/сети (средний приоритет).**
   `setup-status` без cookie отвечает `success=false`; скрипт обновляет блок
   только при `success=true` и глотает ошибку сети
   (`streamer_dashboard.html:1115–1121`). Открытая вкладка может оставить
   старое «всё работает» после истечения сессии или обрыва связи. Нужны время
   последнего успешного ответа и явное состояние «данные устарели / войди снова».

6. **Промокоды принимают некорректные числа (низкий/средний приоритет).**
   `streamer.py:957` и `promo.py:113` приводят `points`/`max_uses` к `int`,
   но не запрещают нулевую/отрицательную награду и отрицательный лимит.
   Активация кода с `points <= 0` расходует применение, не выдавая очков,
   после чего пишет «получил: бонус» (`promo.py:22–90`). Нужны ограничения и
   проверка хотя бы одной реальной награды до сохранения кода.

## Предложения по развитию

- **Админ:** очередь подключённых/ожидающих каналов из существующего
  `/api/admin/channels`, переключатель выбранного канала и отдельная общая
  сводка. Раздел RimWorld сначала привести к работающим админским контрактам.
- **Стример:** рядом со статусом показывать время последнего сигнала мода и
  время обновления самой панели; при потере связи давать одно следующее
  действие. Рядом с аварийной паузой показывать её подтверждённое сервером
  состояние после каждого изменения.
