## 1. Главный принцип

**Успех подтверждается внешним признаком, а не сообщением исполнителя.**

За один день 2026-07-22 этот класс ошибки всплыл четыре раза:

| Что рапортовало | Что было на самом деле |
|---|---|
| Mass Upgrade: «нужен перезапуск» (подразумевая «сохранил») | не сохранял ни у кого с мая |
| Загрузчик Workshop: `Finished...` | не опубликовал ничего |
| Мод RimWorld: команда поставлена в очередь | очередь молча теряла все строки с миграции m1 |
| Расширение: «закон на голосовании» | закон давно принят, статус не обновлял никто |

Отсюда правило на каждую проверку: не «сервис пишет ок», а **запрос в боевую базу /
дата на странице / строка в логе игры / вывод теста**. Ниже под каждую подсистему
дана конкретная такая проверка.

## 3. Бэкапы

**Три независимых механизма, все проверены 2026-07-22 — рабочие.**

| # | Кто | Куда | Формат | Хранит |
|---|---|---|---|---|
| 1 | cron 05:00, `backup_db.sh` | `/root/twitch-extension/backups/viewers.daily.*.db.zst` | сжатые ~8.8 МБ | 15 дневных + 7 недельных |
| 2 | in-process `backup_loop.py` | `/root/twitch-extension/backend/backups/backup_*.db` | **несжатые 65 МБ** | ~15 штук = 910 МБ |
| 3 | **офсайт** | `%USERPROFILE%\shedstream-backups\` на ПК владельца | сжатые | 16 копий |

### Офсайт устроен как ЗАБОР, а не отправка

Задача Windows **`shedstream-db-backup-pull`** (ежедневно 13:00,
`scripts/pull-backup.ps1`) тянет свежий `.zst` с прода на локальный компьютер.

**Искать офсайт grep'ом по серверу бесполезно — его там нет и быть не должно.**
2026-07-22 я на этом ошибочно объявил дыру; владелец поправил.

Проверка:
```powershell
Get-ScheduledTaskInfo -TaskName "shedstream-db-backup-pull"   # LastTaskResult должен быть 0
Get-ChildItem "$env:USERPROFILE\shedstream-backups" | Sort-Object LastWriteTime -Desc | Select -First 3
```

## Как доказать, что бэкап рабочий (а не просто лежит)

**Проще всего — одной командой, с ПК владельца:**
```bash
python scripts/verify-backup.py        # свежий срез;  --all = все 14
```
Разжимает, гоняет `integrity_check`, проверяет что `viewers` не пуста.
Коды выхода: **0** восстановим · **1** битый, разбираться сейчас ·
**2** проверить не вышло (нет пакета `zstandard`) — это НЕ «бэкап плохой».
Разводить 1 и 2 обязательно: ежедневная ложная тревога приучает не смотреть
в лог, и тогда настоящую поломку тоже пропустят.

**Запускается само:** с 2026-07-25 `pull-backup.ps1` вызывает эту проверку
после каждого забора и пишет результат в `pull-backup.log` строкой
`verify: restorable` / `VERIFY FAILED` / `verify: SKIPPED`. До этого
единственной проверкой было «файл больше 1024 байт» — её проходит и архив,
скачанный наполовину. Разовый дрилл 2026-06-13 доказал восстановимость той
копии, но ничего не говорил про скачанную сегодня.

**Вручную, на сервере:**
```bash
# на сервере, где есть zstd
zstd -d -q -f /root/twitch-extension/backups/viewers.daily.YYYY-MM-DD.db.zst -o /tmp/rc.db
python3 -c "
import sqlite3; c=sqlite3.connect('/tmp/rc.db')
print(c.execute('pragma integrity_check').fetchone()[0])
print('зрителей:', c.execute('select count(*) from viewers').fetchone()[0])"
rm -f /tmp/rc.db
```
Плюс сверить MD5 локальной копии с серверной — докажет, что перенос не исказил файл.

Результат теста 2026-07-22: `integrity_check: ok`, 106 таблиц, 76 зрителей,
5 731 423 очков, 22 героя. MD5 совпал.

### Известное к улучшению

Механизм №2 пишет **несжатые** копии: 910 МБ против 355 МБ у cron за тот же охват.
Сжатие сократило бы до ~130 МБ. Не срочно (диск занят на 51%).

## 4. Деплой

```powershell
pwsh scripts/deploy.ps1 -Backend     # только сервер
pwsh scripts/deploy.ps1 -Mod         # сборка + копия DLL в игру + сверка md5
pwsh scripts/deploy.ps1 -All         # мод + бэк + фронт
pwsh scripts/deploy.ps1 -DryRun      # ничего не менять, показать план
```

Если `pwsh` не найден: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\deploy.ps1 -Backend`.

**Что делает сам:** прогоняет критические тесты (красный тест = деплой не пойдёт),
тарит без `*.db`/`.env`, рестартит supervisor, проверяет `RUNNING` + `/health` 200.

**Правила:**
- **фронт не катать, пока идёт ревью Twitch** — только `-Backend`, иначе собьётся
  cache-bust на замороженной версии;
- перед `-Mod` **закрыть игру** — иначе DLL занят;
- прод-деплой во время стрима — только хотфикс падающего.

**Безвредный транзиент:** `tar: timestamp … in the future` — локальные часы впереди
серверных, файлы уже распакованы. Проверить curl'ом и жить дальше.

## 6. Ловушки

Полный список того, обо что уже спотыкались. Каждая стоила часов.

### Тихое проглатывание ошибок
- **`INSERT OR IGNORE`** прощает НЕ ТОЛЬКО дубликат — любое нарушение целостности.
  Так очередь команд RimWorld молча теряла все строки с миграции m1 (нарушение
  `NOT NULL` на `channel_id`). Подавление ошибки должно быть **узким**.
- **Финализатор, который глотает исключение**, меняет вылет на молча сломанную
  функцию. Сначала декомпиль и прицельный фикс, глушить — последнее средство.

### Событие мода не объявлено в манифесте
Новый `PostEventAsync("bannerlord", "hero.X", …)` **молча не работает**, пока
`- hero.X` не добавлен в `modules/bannerlord/manifest.yaml`. Кусало трижды
(`hero.properties_snapshot`, `hero.restore_profile`, `hero.policy_result`).
Симптом: мод пишет «отправил», бэкенд ничего не делает.

### ACK мод-действия не доказывает выполнение
`ActionPoller` подтверждает `success=true` **до** реальной работы. Судить об
исходе по `module_actions` нельзя — нужен отдельный результат-эвент.

### Статус без терминального состояния
Если статус может остаться промежуточным навсегда — его никто не закрывает, и это
баг ещё до того, как что-то сломается. Заявки на законы висели `pending` вечно, а
уникальный индекс по `pending` превратил это в полную блокировку механики.

### Файлы фронта делят ОДНУ глобальную область

`viewer.js` распилили на `pets.js` / `shop.js` / `duels.js` / …, но подключаются
они обычными `<script>` — значит все функции верхнего уровня валятся в общее
пространство. **Два файла с функцией одного имени — законный JavaScript: тот,
что грузится позже, молча заменяет первый.** Ни ошибки, ни предупреждения.

Реальный случай (2026-07-22, час диагностики): `pets.js` и `shop.js` оба
объявляли `async function _buyItem`. `pets.js` подключён позже
(`extension.html:469` против `461`) → **весь магазин RimWorld** уходил в
`/api/pet/purchase`, передавая URL вместо идентификатора, и получал «Предмет
не найден в каталоге» — при полностью исправном каталоге. В nginx-логе
33 запроса к питомцам и **ни одного** к RimWorld.

Чтением кода не ловится: каждый файл по отдельности корректен. Ловится
линтером — `check_frontend_global_collisions` (сверяет только те файлы,
что грузятся одной оболочкой; `const`/`let` не проверяет — их
переобъявление даёт громкую ошибку и потому не опасно).

**Правило:** функции модуля называть с префиксом модуля (`_rwBuyItem`,
`_bnrBuyAction`), а не общими словами.

### Схема в коде разъехалась со схемой миграции
`CREATE TABLE IF NOT EXISTS` на уже мигрированной базе **не срабатывает** —
и код остаётся с досетевой схемой. Проверять обе.

### Мультитенантность
Каждый запрос к тенант-таблице обязан включать `channel_id`. Гейтится линтером,
но `rimworld.py` из проверки **исключён** (`tenant-lint: skip-file`) — и это
исключение спрятало реальный баг ровно того класса.

### Дашборд — это f-строка Python
`routes/streamer.py:_dashboard_html`: любой литеральный `{`/`}` в JS/CSS дублировать.
Перед деплоем — render-тест, иначе 500 на дашборде.

### Windows / оболочки
- в `cmd` `cd` **не меняет диск** — нужен `cd /d`; амперсанд в «Mount & Blade»
  рвёт команду без кавычек;
- PowerShell 5.1: нет `&&`, нет тернарника; `.ps1` без BOM читается как ANSI →
  скрипты держать ASCII-only;
- Python-запись файла без `close()` может не долететь до диска — использовать `with`.

## 9. Ограничения

### Фронт заморожен, пока идёт ревью Twitch
Любая правка фронта = новая версия + ревью (дни). Бэкенд хотфикшится всегда.
**Практическое следствие:** новую активку выпустить нельзя — кнопка не отрисуется
без ярлыка в `BNR_POWER_LABELS`. Обход: переиспользовать свободный ключ с готовым
ярлыком (так вышла невидимость). Свободные на сейчас: `lifesteal_burst`, `disarm_burst`.

### Две валюты, не путать
💎 крустики — платформенные очки (зарабатываются просмотром/чатом).
💰 динары — внутриигровое золото. 1 💎 = 5 динаров. Действие списывает **одну**
валюту по смыслу. Боевые награды — только динары и опыт (решение владельца).

### Платное действие обязано ловить тихий no-op
Движковое «сделай X» часто молча ничего не делает (кап, дубль, нет цели). Хендлер
отдаёт success → списание без эффекта. Детектить по **наблюдаемому** эффекту
(before/after публичными геттерами), не по копии внутренней формулы движка,
и на провале возвращать деньги.

### Заряд и эффект — в одной транзакции
`add_points`/`remove_points` открывают своё соединение и коммитят отдельно. Для
платных действий использовать `add_points_tx`/`remove_points_tx` на общем `conn`,
иначе крах в окне = деньги списаны без эффекта.

## Что проверять первым при «всё сломалось»

1. `curl https://shedoy23.ru/health` → 200?

3. `/var/log/twitchbot.out.log` — свежий Traceback?
4. Открыта ли процессом та база, что ты смотришь (см. §2)?

6. Если мод — смотреть **лог мода**, а не догадки: он пишет и отказы, и причины.

## 10. Локальная копия и поддельный мод

Полный стек на своём ПК: тот же бэкенд, тот же фронт, база — копия боевой из
вчерашнего бэкапа. Twitch о ней не знает, прод не участвует.

```bash
python scripts/local-setup.py      # развернуть; печатает команды запуска
```
Кладёт базу в `%USERPROFILE%\shedstream-local\` — **вне репозитория, намеренно.**
Локальная база рядом с кодом 2026-06-25 положила прод (её журнал уехал в архив
деплоя и затёр боевой). `deploy.ps1` теперь такие файлы исключает, но держать
базу снаружи — вторая линия защиты, независимая от той строки.

Путь к базе бэкенд берёт из `SHEDSTREAM_DB` (по умолчанию `viewers.db` — на
проде поведение не меняется). `FRONTEND_PATH` обязателен, иначе статика не
монтируется и копия открывается пустой (404 на `/static/*`).
Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok","db":"ok"}`,
`/static/extension.html` → 200.

### Поддельный мод — проверка модуля без запуска игры

`scripts/fake-mod.py` подключается по Module API как настоящий мод: здоровается,
шлёт события, забирает команды, подтверждает. Нужен потому, что у RimWorld нет
другого способа себя проверить — владелец в него не играет, и модуль полтора
месяца тихо расходился с реальностью.

```bash
python scripts/fake-mod.py --channel <id> --token <module-token>            # обычная работа
python scripts/fake-mod.py --channel <id> --token <t> --refuse-all          # проверка рефанда
python scripts/fake-mod.py --channel <id> --token <t> --drop-all            # зависшие команды
python scripts/fake-mod.py --channel <id> --token <t> --double-ack          # идемпотентность
python scripts/fake-mod.py --channel <id> --token <t> --send-event <тип>    # одно событие
```
Токен: из папки backend —
`python -c "import sys; sys.path.insert(0,'.'); from routes.streamer import issue_module_token; print(issue_module_token(98319857,'rimworld'))"`

Ловит класс «событие не объявлено в манифесте» мгновенно: отправка неизвестного
типа печатает `ОТВЕРГНУТО: event_not_in_manifest` и выходит с кодом 1. Этот
класс дважды жил в проде незамеченным.

**По не-локальному адресу не пойдёт** без явного `--i-know-this-is-prod`: он
пишет настоящие события в базу.
