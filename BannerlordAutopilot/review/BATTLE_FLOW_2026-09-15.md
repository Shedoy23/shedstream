# Разговор с бандитами и выход после боя

Сообщения владельца 15.09: после исправления F11 игра работает, но ждёт TAB
после победы и реплику «Сдавайся или умри» в разговоре с пиратами.
Скриншоты подтверждают оба состояния. Лог 23:20:41–43 подтверждает преследование
пиратов и выключение до миссии: «идёт встреча с другой партией».

Причины в коде: PollState не поддерживал предбоевой разговор; BattleAutopilotMission
не запрашивал выход. В HANDOFF и DEFERRED это были известные незавершённые пути.
CodeGraph заблокирован (`database is locked`); использованы исходники и локальная
декомпиляция установленных 1.4.8 DLL. Соседнюю ветку свиты не меняли.

Изменение:

- Apply сохраняет выбранную цель EngageParty. Встреча с этой враждебной партией
  бандитов вне поселения/осады больше не выключает автопилот до разговора.
- Каждые полсекунды, в том числе в разговорной миссии, проверяется ConversationParty.
  Выбирается только доступный `common_encounter_ultimatum`; завершённая последняя
  реплика продолжается через ContinueConversation. После неё существующий путь
  encounter→attack запускает полевую миссию.
- Нет выбора по номеру/локализованному тексту. Чужие/мирные партии, F10/F12,
  модальные окна, неизвестные варианты, предложение нанять сдавшихся не нажимаются.
  Разговоры с лордами и решения о судьбе сдавшихся остаются ручными.
- Когда игра установила MissionEnded и MissionResult.BattleResolved, через 3 секунды
  запрашивается BattleEndLogic.TryExit. Вызов идёт с application tick, поэтому
  открытая таблица результатов с остановленными mission ticks не блокирует опрос.
  Отказ движка не обходится; повтор не чаще секунды; после успеха вызовы прекращаются.
  Исключение останавливает автоматические попытки и пишет в лог просьбу выйти TAB.
- Контракт дополнен реально используемыми членами ConversationManager и BattleEndLogic.

Доказательства: AuditRegression на исходнике до изменения — 155 ok / 4 FAIL;
после и с отрицательными сценариями — 165 ok / 0 FAIL. BattleMission — 15/15:
активный бой, модальное окно, запрет движка, однократный выход, F12 и прежнее
управление героем/формациями. EngineContract — 278 ожиданий совпали с игровыми DLL.
Release build — 0 ошибок/предупреждений. Выводы в ../evidence/*conversation*,
*battle-exit*, *battle-flow*. Новое поведение в настоящей игре пока не проверено.

После коммита выполнены мутации: снятие whitelist реплики приводит к FAIL
unknown_option; снятие ограничения MissionEnded/BattleResolved — к FAIL
«активный бой не закрывается». Возврат из собственных копий: исходный diff пуст,
оба прогона exit 0. Итоговая DLL пересобрана без инкремента.
DLL коммита 1dd17cf установлена 23:32:02 при закрытой игре; MD5 совпал с выходом
сборки: 1738012A6498FA8A5367DCAE83D543E0. Резерв предыдущей рабочей версии:
`D:/shedlink-build/autopilot-dll-rollback/BannerlordAutopilot-before-battle-flow-20260915-233202.dll`.

Движок проверен по ConversationManager.DoOption/ContinueConversation и
ConversationVM.OnSelectOption/ExecuteContinue (локальные CampaignSystem и
CampaignSystem.ViewModelCollection). ID ультиматума задаётся AddPlayerLine
в штатном бандитском разговоре; результат войны закрывает close_window.
BattleEndLogic.TryExit из установленной DLL завершает Mission только по своим
условиям; мод не выставляет победу/поражение и не вызывает EndMission напрямую.

Повторить в игре: F11 на карте → преследование пиратов → ультиматум → ответ →
«В атаку» → победа → автоматический выход; отдельно F12 до завершения, поражение,
модальное окно и предложение сдачи. Последующие экраны добычи/пленных этим
изменением не автоматизируются. Проверка победы на скриншоте не доказывает новый код.
