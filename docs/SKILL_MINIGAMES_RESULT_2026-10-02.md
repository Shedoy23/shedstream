## Что сделано

От checkpoint 2 (`752c4a056762d5dfa85fe062369fdcf8447792ff`) создана отдельная
ветка `dot/viewer-skill-minigames-20261002`. Следующая React-панель показывает
морской бой и сапёр. Старая папка `Расширение/frontend`, RPS/канат, их API,
старые рейтинги, сезоны, выплаты и история сохранены. Все предыдущие коммиты
checkpoint 2 остаются предками новой ветки.

Это локальная реализация с настоящими HTTP-маршрутами, серверными правилами,
проверкой JWT и SQLite. Две отдельные вымышленные личности в тестовом стенде
могут сыграть морской бой; сапёр можно пройти через те же API. Статический
`?demo=` — отдельно обозначенные неигровые fixtures, не доказательство
интеграции. `tournament.html` сохраняет прежний макет турнира.

## Правила и данные

- Морской бой: 6×6, флот 3/2/2/1, без касаний, расстановка тапами или серверная
  авторасстановка, готовность двух игроков. Ходы чередуются и после попадания.
  Setup 120 с, ход 45 с, бой 1200 с; опубликован допуск 10 с. Ничья по общему
  лимиту, без случайного выбора победителя. Поиск 300 с, без подставного бота
- Сапёр: 6×6, начальный/продвинутый уровни с 5/7 минами. Начальный решается
  прямыми ограничениями, продвинутый требует вычитания вложенных ограничений.
  Безопасна первая клетка со всеми соседями. Мгновенно решённые первым кликом
  поля отклоняются. Победа требует открытия всех безопасных клеток, не флагов
- Генератор имеет пределы 512 кандидатов, 500000 операций, 1 с; при отказе
  не подставляет случайное поле. Генерация выполняется вне SQLite write-lock,
  с ограниченным допуском параллельной работы
- Сапёр после первого открытия имеет 600 с. Сдача, сброс и обычное истечение
  срока — поражение; подтверждённый сбой сервиса — отмена. Закрытие панели и
  обновление страницы ничего не сдают. Одновременно хранится одна активная
  попытка/партия пользователя в канале
- Новые IDs `battleship`/`minesweeper` используют существующие `duel_stats` и
  `duel_seasons` с channel+game ключами. Старт 1000, K32; начальные условные
  рейтинги задач 1000/1200. Эти числа предварительные, не проверенный баланс
- Результат, сохранение, рейтинг и журнал результата фиксируются одной
  транзакцией. Скорость не даёт бонуса. Правила, K, сложность, таймеры и сезон
  снимком фиксируются в партии; переход через сезон отменяет старую попытку
- За отдельную победу нет крустиков. Новые сезонные выплаты выключены до
  отдельной калибровки/разрешения; прежние выплаты старых игр не изменены
- Секретные записи находятся в новых `skillgame_*` таблицах. Старый generic
  room/state не может их прочитать. Противнику не выдаётся флот, сапёру — мины,
  seed или доказательство решателя. Даже завершение не открывает скрытое поле
- UI-счётчики содержат только семантические названия и количества, без клеток,
  кораблей, раскладок, имён и исходных запросов. Старый контракт счётчиков
  сохранён; новые ключи добавлены отдельным разрешённым набором

Числа приходят из серверного каталога/снимка партии, а не из фронтовых
бизнес-констант. Подробная согласованная граница и ссылки на правила платформы:
[спецификация](SKILL_MINIGAMES_SPEC_2026-10-02.md).

## Что отдельно проверял независимый обзор

Обзор не заменялся успешными тестами. Дополнительные сценарии нашли:

1. Зависшие generation-записи после умершего процесса могли навсегда занять
   допуск канала, пока старые игроки не вернутся
2. Общий обработчик исключений превращал штатные auth403/rate429 в service503
3. No-op запросы с новыми UUID бесконечно накапливали квитанции
4. Изменение общей версии партии соперником стирало несохранённую расстановку
5. Новые валидаторы требовали Pydantic 2, но старый requirements допускал v1

Итоговые исправления и перепроверка приведены в сопроводительных логах и
финальной сводке проверки кандидата. Найденный отдельно узкий случай рестарта
на границе таймера исправлен проверкой heartbeat после дедлайна: свежая запись
до дедлайна сама по себе не доказывает, что сервис работал после него.

## Новая личность, сроки хранения и повторы

Новая панель использует прежний серверный `/api/user/resolve-twitch-token`:
только подтверждённый JWT → Helix → кэш/M122. Она не декодирует токен ради
выдуманного имени и не требует заранее созданного профиля. Невыданный Twitch ID
и ошибка проверки блокируют игру с понятным состоянием; запрос передачи ID
вызывается только отдельной кнопкой. Локальные тесты проходят реальный resolver,
подменяя только внешний OAuth/Helix. Проверено чтение сохранённой связи после
очистки памяти. Реальный вход в Hosted Test остаётся отдельной проверкой.

Квитанции идемпотентности хранятся 24 часа, максимум 4096 на пользователя канала.
Клиент получает срок от сервера, не повторяет старый запрос за пределом окна и
сначала заново читает состояние. Приватные поля/участники становятся кандидатами на очистку через 30 дней;
очистка идёт не более 8 записей за новую команду канала. Полностью неактивный
канал ждёт следующей команды, это не строгий таймер удаления. Журнал
результата и изменения рейтинга остаётся.
Это ограничение временных данных, не обещание постоянного предела всей БД.
Старый ID начала/очереди за пределом окна может считаться новой командой, но
повтор завершённого хода не может ещё раз изменить рейтинг. Дедлайны активных
партий обрабатываются ограниченным серверным проходом даже без опроса игрока.

## Как проверить локально

1. Установить зависимости backend из `Расширение/backend/requirements.txt`
2. В корне `npm ci`, затем `npm --prefix frontend-next ci`
3. `npm --prefix frontend-next test` и `npm --prefix frontend-next run build`
4. `python scripts/run-skillgames-local.py --allow-local-demo --port 4180`
5. Открыть `http://127.0.0.1:4180/extension.html?player=alice` и
   `http://127.0.0.1:4180/mobile.html?player=bobby`. В обеих панелях выбрать
   морской бой для пары; сапёр запускается одиночно
6. Реальный сетевой автопрогон: `python scripts/test-skillgames-network.py`

Локальный runner слушает только loopback, использует временную БД,
синтетические JWT и заменяет Twitch Helper только при локальной выдаче HTML.
Он не запускает основной бот и не подключается к production. БД удаляется
при закрытии стенда. Нельзя использовать этот runner как deployment entrypoint.

## Граница готовности

Push, PR, прод-деплой, установки модов, изменение релизных ZIP и публикация
Twitch не выполнялись. Локальный кандидат не означает готовый CDN-релиз:

- Для локального стенда API same-origin. Для CDN добавлена явная настройка
  сборки `VITE_SKILLGAME_EBS_ORIGIN`: только HTTPS-origin, с синхронным CSP для
  парных входов. Она охватывает вход, игры и счётчики. Адрес из query не берётся,
  production умолчания нет. Перед релизом владелец выбирает реальный EBS и
  проверяет CDN/CORS/Hosted Test; локальный тест не подменяет эту операцию
- Облачный браузер отказал локальному адресу с `ERR_BLOCKED_BY_CLIENT`.
  Доказательства здесь — DOM/unit, ASGI и настоящий TCP/HTTP; визуальный
  просмотр именно 318 px, реальные мобильные устройства и Hosted Test пока
  не подтверждены. Responsive CSS и парные входы сами по себе это не доказывают
- Нужны человеческое балансирование сложности/таймеров, нагрузочный тест,
  оценка накрутки и отдельное решение о сезонных наградах. Внешний решатель
  может помогать игроку даже при корректном сервере
- Нужны актуальная проверка правил Twitch/Apple и новая подача на ревью.
  Предыдущий отказ по азартной ориентации не объявляется закрытым
- Удалять старые RPS/канат и их совместимость можно только после нового
  решения владельца и окончания перехода старого CDN-клиента
