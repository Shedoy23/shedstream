# Шанс смерти героя в бою — Bannerlord 1.4.8 (разбор 23.09.2026)

Источник — декомпиляция игры (`ilspycmd`, 1.4.8.119303), не документация.

## Когда вообще бросается кубик

Только когда здоровье героя падает до нуля. Игра решает «убит или без
сознания» одним броском: `SandboxAgentDecideKilledOrUnconsciousModel.
GetAgentStateProbability` → `1 − PartyHealingModel.GetSurvivalChance(...)`.
В автобое (симуляция) — тот же метод, бросок при ранении героя
(`ApplySimulationDamageToSelectedTroop`). Дробящий урон без особого флага
убить не может никогда.

## Формула (`DefaultPartyHealingModel.GetSurvivalChance`)

Сначала выключатели — шанс смерти 0:
- настройка кампании «Смерть в бою» = Very Easy → бессмертны ВСЕ герои;
- «Смерть в бою» = Easy → бессмертен только главный герой.

Иначе, если у героя есть отряд (`PartyBelongedTo`):

```
D = 1 + лекарь + 0.02·уровень + 0.01·сумма_брони − 0.01·возраст
шанс_смерти = 1 / (51 · D)
```
- «лекарь» = Медицина лекаря отряда × 0.01; в бою НЕ с участием игрока — ×0.25;
- перк Медицины Cheat Death уменьшает шанс ещё;
- только для клана игрока (главный герой, его семья и спутники): настройка
  «Смерть членов клана»: Very Easy → ×0 (бессмертны), Easy → ×0.5,
  Realistic → ×1. На героев зрителей это НЕ действует: они в своих кланах.

**Если у героя нет отряда — шанс смерти 100%** (`D` остаётся 1, ветка без
отряда возвращает `1 − 1/1 = 0` выживания).

## Цифры главного героя (Realistic, на одно падение до нуля)

| герой | лекарь | шанс смерти |
|---|---|---|
| ур. 30, 40 лет, броня 120 | Медицина 150 | ≈ 0,5% |
| ур. 30, 40 лет, броня 120 | нет | ≈ 0,8% |
| ур. 36, **90 лет**, броня 150 | нет | ≈ 0,85% |
| ур. 5, 30 лет, голый | нет | ≈ 2,5% |

**Возраст в бою почти не важен**: 90 лет против 40 — это +0,5 к `D`, то есть
разница в сотые доли процента. Старики умирают не в бою, а от старости —
это отдельное суточное событие кампании (`DiedOfOldAge`).

## Герои зрителей

Мод призывает героя через `SimpleAgentOrigin(hero.CharacterObject)`
(`SummonHeroHandler.cs:454`). Отряд такого бойца для игры — это
`hero.PartyBelongedTo`:
- **у героя есть свой отряд** — формула выше (обычно меньше 1% за падение);
- **героя без отряда** (свежесозданный, сидит в городе) → **100% смерти при
  первом падении**. Именно так 22.09 голые герои L5 гибли 4 раза подряд за
  минуты (`docs/POSTSTREAM_TRIAGE_2026-09-22.md`, п. 4). ТОЧНО по коду,
  ВЕРОЯТНО для конкретных героев: отряд в логе не пишется, а в зеркале
  `party_info_json` пусто у 20 из 30 живых героев — у части из них отряд
  может быть чужой.

С патчем смены Codex `ViewerBattleMortalityPatch` (установлен в игру
23.09 00:12, коммит `172b354` в ветке `codex/viewer-battle-mortality-current`,
**на GitHub не запушен**): шанс смерти зрителя = 5% от ванильного:
- со своим отрядом: ≈ 0,03–0,1% за падение;
- без отряда: **5% за каждое падение** — то есть бессмертным его не назвать,
  при 20 падениях за вечер это ≈ 64% погибнуть.

## Решение владельца 23.09: один шанс для всех — 0,1% за падение

«Надо для всех зрителей один шанс, и очень маленький: призывают 5–10 раз за
бой». `ViewerBattleMortalityPatch` теперь ставит выживание героя зрителя
ровно `1 − 0.001` вне зависимости от отряда, уровня, брони и возраста
(константа `ViewerDeathChance`). Гарантированное выживание (дробящий урон,
«Very Easy») не трогается, NPC и солдаты — тоже.

Что это значит: 10 падений за бой → ≈1% погибнуть за бой; 100 падений за
вечер → ≈10%. Смерть от старости патч не трогает.

Коммит `a4c4fd2`; проверка ViewerMortalityHarness красная 6/3 на правиле
«5% от ванильного», зелёная 9/0 после; Release 0/0. Установлено 23.09 при
закрытой игре, SHA-256 DLL `1A1FA4A2…`, откат —
`D:/shedlink-build/dll-rollback/20260923-viewer-flat-death` (там сборка
Codex `4A4E7C61…`). **В бою не проверено.**
