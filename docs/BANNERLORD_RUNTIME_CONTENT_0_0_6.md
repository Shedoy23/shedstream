# 0.0.6: игровые каталоги — локальная реализация

28.09.2026. Рабочая копия: `C:\Users\Edward\Desktop\work\0.0.6`.
Это первый срез устранения хардкодов, не завершение всего аудита.
Production, установленный мод и Twitch ZIP 0.0.5 не обновлялись.

## Что изменилось

- Культуры создания героя и законы больше не выбираются из ручных списков JS/Python.
  Мод сообщает содержимое загруженной игры, названия и описания.
- Для культуры мод проверяет наличие подходящего шаблона Wanderer. Явный выбор
  недоступной культуры заканчивается отказом, а не созданием героя другой культуры.
- Навыки и атрибуты отображаются по полученным значениям; новые ключи не исчезают,
  отсутствующие ванильные строки не придумываются. Модовые ID сохраняют регистр.
  Значения выше 5/10 не вызывают ошибку построения индикаторов.
- Экран снаряжения показывает неизвестные характеристики, включая нули,
  отрицательные значения и текст. Для неизвестной характеристики числовая разница
  не объявляется автоматически улучшением или ухудшением.
- Backend сохраняет переданный игрой `required_level` предмета. Для старого мода,
  который не передал поле, остаётся прежний fallback по тиру.

## Контракт

`module.catalog_update` принимает четыре новых полных каталога:
`cultures`, `policies`, `skills`, `attributes`.

```json
{
  "catalog": "cultures",
  "save_id": "campaign-id",
  "equipment_session_id": "load-nonce",
  "catalog_seq": 1,
  "entries": [{
    "id": "Mod.Culture-X",
    "name": "Название из игры",
    "description": "Описание из игры",
    "available": true
  }]
}
```

Все чтения объектов движка выполняются в игровом потоке. В сетевую отправку
уходят готовые строки; повтор после ошибки сохраняет тот же снимок и номер.
Снимки, включая пустые, периодически повторяются через существующий publisher.

M134 хранит последние снимки отдельно по каналу и типу каталога. Backend
принимает только текущие save/session и возрастающую ревизию. При смене сеанса
старые записи не становятся доступными новому сеансу. Новая сессия начинает
ревизию заново. Пустой полученный каталог отличается от ещё не полученного.

`GET /api/bannerlord/content-catalogs` требует viewer JWT и возвращает текущую
идентичность и `{available, reason, entries, catalog_seq}` для каждого полученного
каталога. У недоступного каталога нет `catalog_seq`.

Создание героя проверяется до оплаты и повторно внутри транзакции очереди.
UI передаёт `content_context: {save_id, equipment_session_id}` того снимка,
по которому показал выбор. Это условие актуальности, а не источник полномочий.
Backend отклоняет смену контекста и сам назначает `save_id`,
`equipment_session_id`, `content_catalog_seq` для команды моду.
Мод повторно проверяет save/session и доступность культуры перед созданием.
Случайный выбор без нового каталога сохранён для старого мода; явный выбор
культуры требует актуального каталога. Поэтому выкатывать новый backend отдельно
от подготовки модов без проверки этого перехода нельзя считать подтверждённой
совместимостью всех сценариев старого клиента.

Наличие закона в каталоге не означает разрешение конкретному герою принять его.
Существующие проверки прав и игрового результата остаются отдельными.

## Границы этого среза

- Не менялись баланс, цены и пределы действий покупки фокуса/атрибутов.
  Интерфейс больше не выдаёт эти пределы за универсальные пределы игры.
- Мод по-прежнему описывает поддержанные native ItemObject/слоты и известные
  ему свойства. Новые обычные предметы модпака обнаруживаются через реестр;
  это не обещание автоматически понимать любые сторонние системы магии,
  типы слотов или произвольные свойства других модов.
- Не реализованы общий capability/action contract, перенос остальных правил
  backend в игру, новые BLT-механики, изменения RimWorld и marketplace.
- Старый state-update протокол обновляет строки навыков/атрибутов через UPSERT.
  Автоматическое удаление устаревших строк после изменения модпака требует
  отдельного явного контракта полного снимка; этот срез его не вводит.
  Только исторические дубли регистра известных vanilla skills объединяются
  при отображении, если каталог не объявляет их разными объектами.
- Миграция M134 относится к зеркалу backend. Новый сохраняемый тип в кампанию
  не добавлен; новые metadata-каталоги пересобираются из текущего мира.
- Нужен живой повтор: vanilla и модпак, создание культуры, отсутствие шаблона,
  закон, смена/перезагрузка сохранения, отказ и повтор после обрыва связи.
  Локальные harness-тесты и сборка не подтверждают эти игровые сценарии.

Исторический аудит находится в `version-0.0.6/hardcode-audit/`.
Его probes и source hashes описывают исходный снимок до исправлений;
`verify_audit.py` не является проверкой неизменности новой реализации.
