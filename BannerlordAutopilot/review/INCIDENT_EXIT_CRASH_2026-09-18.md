# Разбор смены 18.09: вылет игры в 14:34 и коммиты Codex

Смена Claude после Codex. Разбор обязателен по `AGENTS.md` §1 — это вторая
голова, а не формальность. Игра во время смены была запущена владельцем, DLL не
трогалась.

## 1. Вылет 18.09 14:34:34 — причина названа и доказана

**Что случилось.** Игра закрылась с `0xC0000005` (доступ по нулевому адресу)
через шесть минут после установки `7490aa0`. Владелец потерял ~5 игровых дней и
186 бойцов: сеанс продолжился с сохранения (недели 13343 → 13338, отряд 215 → 29).

**Цепочка доказательств.**

1. Стек из дампа (`evidence/crash-20260918-143427-stack.txt`, снят
   `dotnet-dump analyze`, сам дамп игра уже удалила после отправки):

   ```
   IncidentsCampaignBehaviour.<InitializeIncidents>b__25_553(TextObject)
   Incident.CanIncidentBeInvoked()
   Campaign.Tick()
   MapState.OnMapModeTick(Single)
   ```

2. Какая это лямбда — не догадка: IL этого метода взят из самой игровой DLL
   (`ilspycmd TaleWorlds.CampaignSystem.dll -t ...IncidentsCampaignBehaviour -il`).
   Она зарегистрирована при `ldstr "incident_hammer_of_the_sun"` и в теле имеет
   ровно одно разыменование без проверки:

   ```
   IL_0054: callvirt MobileParty::get_CurrentSettlement()   // → локальная 0, без проверки на null
   ...
   IL_00db: ldloc.0
   IL_00dc: callvirt Settlement::get_Name()                 // ← NullReferenceException
   ```

   Все остальные выходы метода защищены (позиция, пустыня, <50 регуляров, <10
   не-асерайцев, null-персонаж). То есть единственный возможный null здесь —
   `MainParty.CurrentSettlement`, а он пуст ровно тогда, когда партия УЖЕ вышла.

3. Почему условие вообще считается вне поселения. Движок кладёт выпавшее
   событие в очередь на входе (`IncidentsCampaignBehaviour.InvokeIncident`,
   190449-190456), а проверяет его на СЛЕДУЮЩЕМ `Campaign.Tick`
   (10136-10143). У человека между входом и выходом проходят минуты, у
   автопилота — доли секунды. Журнал мода:

   ```
   14:34:27  ПРИБЫЛИ в «Хубьяр» (прибытие #20)
   14:34:27    ВЫШЛИ из «Хубьяр» (подтверждённый выход #20)
   14:34:27    НОВАЯ ЦЕЛЬ #31: GoToSettlement → Ливас
   [журнал обрывается; дамп записан 14:34:34]
   ```

4. Условия события в этот момент выполнялись: пустыня (асерайские земли,
   Малуль → Хубьяр → Ливас), 215 бойцов, смешанный состав, и только что нанятые
   восемь асерайских новобранцев — последнее условие стало истинным именно
   благодаря новому кругу найма.

**Это класс, а не один случай.** Разбор всех 101 ванильного события: условия
пяти из них читают `MainParty.CurrentSettlement` без проверки на null, и у всех
пяти триггер — «вход»: `hammer_of_the_sun` (193255), `through_proper_channels`
(192377), `the_quiet_life` (192768), `occupational_safety` (192852),
`jobs_for_the_lads` (192925). Ещё важнее: событие, которое так и не показали,
на кулдаун не встаёт (`Cooldown` пишется при показе), поэтому вылет
воспроизводился бы при каждом заезде в пустынный город с такой партией.

**Починка.** `3762c3c`: автопилот не выходит из поселения, пока в
`MapState.NextIncident` что-то лежит. Событие показывается штатно и разбирается
тем же `TryHandleMapIncident`, что и раньше; предел ожидания — 20 опросов (10 с),
после него очередь снимается самим модом с записью в журнал, чтобы не встать в
поселении навсегда. Ванильный код не патчится (у автопилота нет Harmony) —
чинится вход в него, как требует правило «repair, а не swallow».

Гейты: красный стенд `982f187` — 465 ok / 5 FAIL, после правки 470/470;
контракт реальных DLL 491/491 (добавлено ожидание `MapState.NextIncident` — если
в новой версии игры его переименуют, автопилот не включится, а не упадёт);
`BattleMission` — ok; сборка 0 предупреждений / 0 ошибок.
**Живой прогон не выполнен — DLL не ставилась, игра запущена.**

## 2. Коммиты Codex

### `7490aa0` — приоритет найма (установлен 18.09 14:28)

- **Верно по движку.** `SettlementServices.HasAffordableRecruits` намеренно не
  зовёт `CanMainHeroRecruitTroops` (он читает `Settlement.CurrentSettlement` и на
  карте соврал бы), а считает по `HeroHelper.HeroCanRecruitFromHero` +
  `PartyWageModel`. Это ровно то, что записано в HANDOFF, и это правда.
- **Подтверждено журналом.** 14:40–18:10 отряд вырос 29 → 223 при цели 90%
  от 273; посещения не повторяются благодаря отметкам обслуживания и
  `_recentTownVisits`.
- **Побочный эффект, который никто не закладывал:** темп. Вход и выход за одну
  секунду — новое для движка состояние, и оно вскрыло дефект §1. Сам коммит
  ничего не сломал; он сделал достижимым чужой дефект.
- **Замечание по гигиене:** в одном коммите с наймом приехали разговоры
  (освобождённый герой, сценарные встречи, бой с караваном) и правки боевой
  миссии — 342 строки в одном файле. Откатить наём отдельно теперь нельзя.

### `04a8059` — спешивание героя на штурме
