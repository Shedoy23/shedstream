# AGENTS.md — для Codex и других агентов в этом репозитории

Владелец ведёт работу посменно: то Claude, то Codex (у обоих кончаются лимиты), и
намеренно — две независимые головы лучше одной. Правила проекта одни для всех.

## Прочитать перед работой

- `CLAUDE.md` в корне — правила проекта. **Обязательны и для Codex**, хотя написаны
  для Claude. При расхождении с этим файлом прав `CLAUDE.md`.
- `LESSONS.md`, часть 2 — личные правила владельца: он не программист, отвечать
  по-русски простым языком, сводка в конце — это интерфейс; честность выше вежливости.
- Работаешь с автопилотом Bannerlord — ещё `BannerlordAutopilot/HANDOFF.md`.

Самое частое, что теряется без этих файлов:
- тест сначала показать красным на старом коде и закоммитить, потом исправление;
- судить о прогоне по коду возврата;
- найденное, отложенное и решения владельца записать в ту же сессию: `DEFERRED.md`,
  `STATUS.md`, урок — `LESSONS.md`; чат записью не считается;
- не утверждать поведение в игре без строки журнала игры или мода.

## Посменная работа над автопилотом (`BannerlordAutopilot/`)

1. **Начало смены.** Прочитать `BannerlordAutopilot/HANDOFF.md`. Разобрать коммиты
   другого агента после последней записи: что сделано, верно ли по коду движка
   (`D:\shedlink-build\bl-decomp`), подтверждено ли журналом игры. Разбор — файлом в
   `BannerlordAutopilot/review/`. Это и есть вторая голова, а не формальность.
2. **Не оставлять незакоммиченного в конце смены.** Готовое — коммит. Недоделанное —
   коммит `wip(autopilot): …` и строка в HANDOFF. Иначе следующий агент либо затрёт
   чужую работу, либо закоммитит её, не проверив.
3. **DLL в игру.** Ставить только при закрытой игре. Записать в HANDOFF: коммит,
   md5, время, где копия для отката.
4. **Решения о продукте — за владельцем.** Бой или отход, выбор вариантов событий,
   собственные оценки целей вместо штатных: предложить с рекомендацией, молча не делать.
5. **Конец смены.** Обновить `BannerlordAutopilot/HANDOFF.md`.
