## Почему у shedcolony архитектура лучше

```java
// ShedActions: решение об ACK принимает ОДНО место
String err = handler.apply(...);        // null = успех, иначе код ошибки
if (err == null) { ShedSeen.record(actionId); ShedNet.ack(actionId, true, null); }
else             { ShedNet.ack(actionId, false, err); }
```

Три свойства, которые из этого следуют:

1. **Обработчик не может случайно отрапортовать успех** — он вообще не умеет
   отвечать ядру. Он возвращает исход, отвечает диспетчер.
2. **Забыть сообщить исход невозможно** — метод обязан что-то вернуть.
3. **Дедуп пишется ТОЛЬКО на успехе.** Удавшееся действие с потерянным ACK
   подтверждается повторно без повторного выполнения; провалившееся —
   переигрывается. Ни двойного эффекта, ни ложного «уже сделано».

## Почему в Bannerlord иначе — и почему это не лень

Работа с движком обязана идти в главном потоке игры, поэтому `ExecuteAsync`
отвечает ядру `(true, null)` **сразу** — это «заявка принята», — а настоящая
работа уходит в очередь. Исход физически становится известен позже.

Отсюда второй канал: `ActionFeedback.PostFailed(actionId, reason)`. Он работает
и он зрелый. Проблема не в нём, а в **умолчании**:

```csharp
private bool _handlerSuccess = true;   // MainThreadDispatcher.TrackedAction
```

Обработчик, который ничего не сказал, считается успешным. Значит любой забытый
путь отказа превращается в ложный успех — и деньги не возвращаются.

## Целевой контракт (к чему идём)

**Обработчик обязан НАЗВАТЬ исход. Ровно один раз, на каждом пути выхода.**

```csharp
// отказ — на КАЖДОМ выходе, где эффекта не будет
ActionFeedback.PostFailed(actionId, "prisoner");
return;

// успех — только после того, как эффект ПРОВЕРЕН
ActionFeedback.PostApplied(actionId);
```

Правила, одинаковые для всех модов:

1. **Успех — утверждение, а не умолчание.** Говорить «получилось» можно только
   после наблюдения эффекта: сверить состояние до и после публичным геттером
   («атрибут вырос»), либо увидеть созданный объект («WorkOrder появился»).
   Копировать внутреннюю формулу движка нельзя — она меняется с патчем игры.
2. **Ноль эффекта — это отказ.** Кап, дубль, нет цели, оффлайн — всё это `Fail`,
   а не «успех, просто ничего не изменилось».
3. **Списал в игре и не получилось — верни в игре.** Крустики вернёт ядро по
   `PostFailed`; внутриигровые деньги обязан вернуть сам мод
   (`HeroGoldCharge.Refund` — образец в `AddAttributeHandler`).
4. **Исключение — тоже исход.** `catch` обязан заканчиваться `PostFailed(...,
   "crashed")`, иначе краш выглядит как успех.
5. **Дедуп пишется на успехе, а не на попытке.**

### Образцы, на которые смотреть

| Что | Где |
|---|---|
| отказ на каждом пути, включая «эффекта не было» | `DiplomacyHandlers.cs` |
| проверка эффекта + возврат внутриигровых денег | `AddAttributeHandler.cs` |
| централизованное решение об ACK + дедуп на успехе | `ShedActions.java` (shedcolony) |

## Как идём — по шагам

**Шаг 1 — сделать умолчание видимым. СДЕЛАНО 2026-08-23.**
Поведение НЕ изменено: переключать умолчание на отказ разом для 64 обработчиков
без запущенной игры нельзя. Вместо этого действие, завершившееся без явного
исхода, пишет в лог стримера:

```
[action] БЕЗ ЯВНОГО ИСХОДА action_id=… — успех проставлен умолчанием;
         обработчик не подтвердил эффект
```

Это тот же приём, что `channel-default:` на бэкенде: пока дефект молчит, его
нельзя ни найти, ни посчитать. Строки в логе = рабочий список того, что осталось
перевести.

**Шаг 2 — переводить обработчики по одному**, начиная с денежных. Готово:
`CreateKingdomHandler` (было шесть молчаливых выходов из семи).

**Шаг 3 — когда список в логе опустеет**, переключить умолчание на отказ:
`_handlerSuccess = false` до явного `PostApplied`. После этого забыть исход
станет невозможно — как в shedcolony.

**Шаг 4 — RimLink**: переводить, только если модуль возвращается в строй.
Сейчас вкладывать в него работу незачем.

## Чего этот документ не делает

Он не доказывает, что действия работают в игре. Ни одна правка мода не
проверяется автотестом — их нет и не предвидится. Любая правка здесь
**правдоподобна, но не проверена, пока не сыграна**.
