# Журнал моментов и мысли автопилота

Установлено 27.09.2026: `C:/Users/Edward/Documents/ShedLink/stream-director`, источник «ShedLink — мысли ИИ» в OBS, сцена «ИГРА с вебкой», автозапуск при входе в Windows. Наблюдатель подключён к OBS 32.2.2. Тестовая карточка проверена снимком самого OBS; рабочий источник прозрачен при выключенном ИИ. Реальная запись с паузой ещё не проверена.

Локальная первая версия, 27.09.2026. Автономный наблюдатель Node.js 24, без npm-зависимостей. Читает существующие журналы BannerlordAutopilot и BannerlordLink; не меняет игру, сохранения, сервер, OBS-сцены или Twitch-фронт.

## Что готово

- Сбор боевых эпизодов, объединение начала, участников и итогов в одну запись. Уникальные герои; повторный призыв не увеличивает счётчик. Погибшие не теряются из-за отсутствия выплаты.
- Приоритеты: штурм, много противников на старте, от 10 героев участников, гибель героя. Это кандидаты для монтажа, качество кадра ещё нужно оценивать по видео.
- HTML, CSV и JSON с объяснением приоритета и ссылками на строки исходных журналов. При наличии непрерывных OBS-отсчётов — таймкод и рамки клипа с запасом до 20 секунд до и 15 после события, ограниченные реально наблюдавшейся записью.
- Новый локальный OBS-оверлей: свежая мысль, тип события, число замеченных героев, итог боя, предыдущая мысль. Данные о размере войска становятся доступны из существующих логов только при подведении итогов; неизвестные значения не дорисовываются.
- Пустой файл мыслей скрывает карточку. Через 180 секунд без обновления она также скрывается. При потере локального сервера — после двух неудачных запросов. Прототип не доказывает, что процесс ИИ жив: в исходном текстовом файле нет отдельного heartbeat.

## Запуск

Запустить `Start.ps1` от обычного пользователя Edward. Требуется Node.js 24; скрипт использует уже установленный runtime Codex или `node` из PATH. Остановить Ctrl+C. Launcher сохраняет информацию в `%LOCALAPPDATA%/ShedLink/stream-director/state/`. Прямой вызов `node server.mjs serve` без `--state` сохраняет её рядом в `state/`. Второй процесс с тем же state блокируется.

Предпросмотр без связи с OBS: `./Start.ps1 -PreviewOnly`.

В OBS для будущего подключения: браузерный источник `http://127.0.0.1:17863/overlay.html`, размер 680×440. Фон прозрачный. Старый текстовый источник оставить как вариант отката и скрыть только после проверки нового. Страницу с `?demo=1` в эфир НЕ ставить: там явно помеченные примерные данные.

Для таймкодов включить существующий OBS WebSocket v5 на localhost:4455. Launcher читает существующий пароль OBS из его локального конфига через `--obs-config`. При ручном запуске можно передать переменную окружения `OBS_WEBSOCKET_PASSWORD`; не вписывать в URL, документы или Git. Запускать наблюдатель **до начала записи**. Он только читает `GetRecordStatus` и события записи — не запускает, не останавливает и не меняет OBS.

Текущие ограничения синхронизации:

- Без OBS остаётся полезный журнал с часами компьютера. Эти часы не подменяют время видео.
- Подключение посреди записи или восстановление разорванного WebSocket требует нового достоверного начала записи; до этого таймкоды отсутствуют. Наблюдатель сам ничего не перезапускает.
- Паузы создают разрыв: отметка начала может сохраняться, но цельный клип через пропущенную часть не выдаётся (`recordingGap`).
- Автоматическое разделение записи на файлы пока инвалидирует привязку до следующей записи. Смещение внутри split-файла не угадывается.
- Имя записи становится известно на штатной остановке. До этого есть ID записи и время, путь может отсутствовать.
- Частота опроса 1 с, оценка точности 1.5 с; это монтажные ориентиры, не покадровая разметка.

Протокол: https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md (`GetRecordStatus`, `RecordStateChanged`, `RecordFileChanged`).

```powershell

```

Дополнительный `--clock` принимает сохранённый JSONL отсчётов наблюдателя. Время исходных журналов по умолчанию Екатеринбург (`--offset +05:00`). Нельзя подставлять время старта Twitch вместо старта записи OBS: остановки эфира и паузы записи независимы.

## Семантика источников

`MissionBehaviors registered` означает создание миссии, не начало боя. Бой подтверждается фактической расстановкой/завершением из автопилота или resolved-выплатой Link. После подтверждения вход в миссию может служить приблизительной левой границей клипа, если строки расстановки нет.

`Participation applied to N/M` — M уникальных зарегистрированных героев (включая аккаунт стримера, если его герой зарегистрирован), а не число живых или активных людей в чате. `enemies` и `won` в payout относительны стороне конкретного зрителя: финальная сторона берётся из Participation. Глобальный исход — `playerVictory` с подтверждением разрешённого боя. Неизвестный тип называется «Бой», а не автоматически полевой. Неизвестный исход не называется поражением.

Пока не реализованы: оценка соотношения полных армий прямо при старте, героические серии убийств, захват/дарение владений, тематические сюжетные цепочки, автоматический монтаж, стрим-маркеры Twitch. Для точного live-снимка армий лучше добавить отдельное структурированное событие мода следующей версией.
