# Спека: возвращение ассасина + активка «Невидимость»

Статус: **проработано, не реализовано.** Блокер — заморозка фронта на ревью Twitch.
Дата: 2026-07-21.

## Зачем

Ассасин сейчас скрыт (`deprecated=1`, миграция m92), потому что после урезки до
6 классов он был «берсерк, но с другим названием» — своей механики у него не было.
Невидимость даёт ему уникальную роль: не танк и не дамагер, а «проскользнул сквозь
строй и выбил ценные цели». Возвращать ассасина имеет смысл **только вместе с ней**.

## Механика (решение владельца, 2026-07-21)

Ассасин слабо бьёт и умирает от сплеша/шальных стрел — поэтому длительность
полная, как у остальных баффов: **45 секунд**, а не «короткий рывок».
Цель — дать зрителю окно, чтобы реально набить киллы, а не просто сбежать.

| Параметр | Значение | Почему |
|---|---|---|
| Длительность | 45 с | как у остальных активок, единый код баффов |
| Кулдаун | как у сигнатурных активок классов | — |
| Цена | тир сигнатурной активки | — |
| Разрыв при ударе | **нет полного разрыва**, см. «Всплеск» ниже | иначе активка бесполезна для своей же роли |
| Работает в турнире | **нет** | турнир — арена 1×1, активки там отключены (общее правило) |

### Всплеск после удара (рекомендуется)

Не «ударил — раскрылся навсегда», а **на ~3 секунды после успешного попадания
ближние враги снова видят цель**, потом снова теряют. Это даёт стиль «ударил и
растворился», сохраняет 45-секундное окно и при этом наказывает за жадность:
если рубить в гуще толпы без пауз — засекут и задавят.

Если по ощущениям окажется слабо — этот пункт снимается одной константой.

## Реализация

**Готовой невидимости в движке НЕТ.** Проверено по декомпилю `Agent.cs`:
`SetVisible` — только меши (косметика), флага «не таргетить» не существует.
Выбор цели нативный (`MBAPI.IMBAgent.*`), Harmony его не перехватит.

Рабочий подход — **срыв захвата цели**, только публичный API, без патчей движка:

```
каждый быстрый тик (0.5 c, COMBAT_AI_INTERVAL уже есть в PowersMissionBehavior):
    для каждого живого враждебного агента e:
        если e.GetTargetAgent() == герой:
            e.InvalidateTargetAgent()
```

Подтверждённые публичные методы (`Agent.cs`):
`GetTargetAgent()` :2809, `SetTargetAgent()` :2814, `InvalidateTargetAgent()` :3691,
`IsActive()` :3223, `Position` :676, `Defensiveness` :1076.

Свойства (важно понимать честно):
- Это **не** неуязвимость. Сплеш, шальные стрелы, конница на скаку, замах, уже
  начатый до сброса — всё проходит. Ровно то, что владелец и описал.
- Между «враг перезахватил цель» и нашим сбросом есть окно до 0.5 с — визуально
  читается как «враги дёргаются и теряют его», а не как выключенный ИИ.
- Стоимость по производительности: один проход по агентам раз в 0.5 с. Дёшево.

### Отвергнутый вариант: смена команды

`Agent.SetTeam()` существует и дал бы «настоящее» игнорирование, но ломает слишком
многое: герой вылетает из формации, ломается наш detach-механизм, атрибуция киллов,
союзники перестают поддерживать, под вопросом собственный урон героя. **Не делать.**

## Блокер по срокам

Фронт рисует кнопку силы так:

```js
const meta = BNR_POWER_LABELS[p.power_key];
if (!meta) return '';   // нет ярлыка → кнопки нет вообще
```

Новый `power_key` без ярлыка во фронте = **кнопки у зрителя не появится**.
Фронт заморожен до вердикта Twitch → выпускать после разморезки, одним пакетом:
снять `deprecated` у ассасина + бэк-логика + ярлык во фронте.

Общее правило, которое отсюда следует: **любая новая активка не может выйти,
пока фронт заморожен** — бэк-часть можно готовить заранее, релиз всё равно ждёт фронт.
