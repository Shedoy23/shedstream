# Отложено сознательно

Живой журнал того, что мы решили **не делать сейчас** — с причиной и с тем, что
это разблокирует. Не бэклог «когда-нибудь»: сюда попадает только то, по чему было
принято решение отложить.

Зачем: без такого списка отложенное либо теряется, либо всплывает третий раз как
«а давай обсудим» — и обсуждается заново с нуля.

**Правило ведения:** решили отложить — строка сюда в ту же сессию. Сделали —
строка удаляется (история в гите). Раздел «Решено НЕ делать» не чистится: он
существует, чтобы не возвращаться к закрытым вопросам.

## 🥇 СЕССИЯ №1 ПОСЛЕ ВЕРДИКТА TWITCH — полный аудит работы

Первое, что делаем после ответа Twitch (одобрение ИЛИ доработка — неважно):
**аудит работы** (новый тип сессии, ROADMAP §6). Не чтение кода — прогон каждой
платной механики всех трёх модулей от кнопки до наблюдаемого эффекта на боевых
данных. Владелец за игрой (стрим + игры запущены), Клод снимает эффект с базы и
логов.

Почему именно первой: за прошедший месяц баги всплывали ПО ОДНОМУ, когда на них
натыкался зритель на стриме, — потому что аудит работы нельзя провести без
запущенной игры. Один целенаправленный вечер соберёт то, что иначе капает
месяц по жалобам. Проверять по НАБЛЮДАЕМОМУ эффекту (списалось → произошло в
игре → в базе → видно зрителю), а не по ответу эндпоинта.

Охват: Bannerlord (классы/силы/приказы/законы/оплата за бой), RimWorld (весь
магазин — уже знаем про переплату за гены и мёртвый _buyItem, проверить
остальное), shedcolony. Найденное — в фикс-очередь с доказательством на каждый.

  что каждый id из фронта существует в игре — ловит разъезд после патчей
  Bannerlord автоматически (иначе кнопка молча перестанет работать).

  единицы. Сгладить хвост = **ослабить берсерка**, чего мы избегаем осознанно
  (11 зрителей из 18 на нём). Решать по фактическим цифрам, не по ощущению.
- [ ] **Убийца беден** — по симуляции ×1.5 против ×3.8 у стрелков: мало киллов,

- [ ] **Конный лучник.** У класса 0 игроков, и мы (m95) сняли ему вампиризм
  19.5% — самый высокий в ростере. По роли правильно, но забирать сустейн у
  класса, который никто не берёт, спорно. Если так и останется пустым — дать

- [ ] **Пороги ачивок протухли.** «Богач» = 500 тыс. при максимуме у игрока

## C2. Аудит фронта на общую глобальную область (после разморозки)

Заказан владельцем 2026-07-22 по следам бага, который съел час: `pets.js` и
`shop.js` объявляли одноимённую `_buyItem`, и весь магазин RimWorld уходил в
эндпоинт питомцев (детали — `RUNBOOK.md` §6).

- [x] **Линтер уже закрывает базовый случай** — `check_frontend_global_collisions`
  ловит одинаковые имена функций и `var` верхнего уровня среди файлов, которые
  грузятся одной оболочкой. Проверен на историческом баге: падает, называет
  проигравший файл. Сейчас коллизий ноль.
- [ ] **Ручной аудит того, что линтер поймать не может:**
  - общие изменяемые глобальные переменные, которые пишет один модуль, а читает
    другой (линтер видит только объявления, не обращения);
  - функции, выглядящие «внутренними» (`_имя`), но по факту глобальные — их
    может позвать кто угодно, и переименование где-то ещё сломает вызов;
  - модули, зависящие от глобалей, объявленных в других файлах: порядок
    подключения в `extension.html` и `mobile.html` становится неявным
    контрактом, и он нигде не зафиксирован;
  - расхождение состава/порядка скриптов между двумя оболочками.
- [ ] **Заодно решить:** не перевести ли модули на `type="module"` или хотя бы
  на обёртку-IIFE — тогда класс исчезает архитектурно, а не проверкой.
  Это правка фронта → после одобрения Twitch.

**Почему не сейчас:** любая правка фронта = новая версия + ревью. Линтер уже
не даст добавить НОВУЮ коллизию, так что срочности нет.

## E. Заморожено до отдельного решения

- [ ] **Обновить Bannerlord 1.3.15 → 1.4.5** (решение владельца 2026-07-22).
  Обновление игры ломает моды системно: Harmony патчит методы по имени и
  сигнатуре. У нас три мода, **два публичных в Workshop** — цена незамеченной
  поломки выше обычной. Порядок: обновить игру → пересобрать все три →
  обновить `DependentVersion` в SubModule.xml → прогнать
  `lint_consistency.py` (поймает переименованные id законов) → проверить в
  бою, что патчи нашли цели (при ненайденном методе они тихо пропускаются:
  мод «работает», а функции нет) → и только потом перезаливать публичные моды
  с проверкой даты на странице Workshop. Подробности — в памяти
  `project_bannerlord_145_upgrade.md`.

- [ ] **GitHub у laitru** (разработчик BLT) — предлагал посмотреть его решения.
  Владелец: «отложи пока». (2026-07-20)
- [ ] **Спека B: kingdom reconcile** — клан в двух королевствах.
  `Расширение/docs/SPEC_KINGDOM_RECONCILE.md`, не реализовано.
- [ ] **Walls-B: авто-штурм атакующих по лестницам.**
- [ ] **«Купить феод»** — за стабильностью, не раньше.
- [ ] **Бэкенд-гигиена:** `rimworld sync_pawn` без `channel_id`; поллер с
  невалидным JWT раз в 5 минут.
- [ ] **Память-сторож на проде.** VDS = 1 ядро / 1 ГБ RAM / 15 ГБ NVMe.
  Замер 2026-07-22: CPU load 0.22 (потолок 1.0), RAM занято 425/961 МБ
  (приложение ~120 МБ), swap 1 ГБ почти не тронут, диск 51%. Запаса много,
  **но RAM — первый кандидат на потолок под ростом аудитории** (не от времени,
  а от числа одновременных зрителей). Добавить простой сторож: свободная память
  ниже ~100 МБ → уведомление (как UptimeRobot дёргает /health). Тогда о
  приближении к пределу узнаём заранее, а не по тормозам на стриме. Апгрейд до
  2 ГБ решит надолго, если после релиза придёт 30–50 зрителей разом.
  Диск не горит: сжать несжатые бэкапы (`backup_loop.py`, 910 МБ → ~130 МБ)
  можно попутно.
