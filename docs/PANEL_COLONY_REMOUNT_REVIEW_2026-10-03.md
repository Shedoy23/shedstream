## Реализация и проверка

ColonyController хранит action state по ключу `shedcolony/channelId/login`
на время своей жизни. JWT в ключ не входит. Компонент читает busy/uncertain/message
из контроллера. Приём нового действия проверяет текущий client, active_module
и прежнее состояние этого owner; освобождают его только определённые ответы.
Завершение запроса обновляет запись исходного owner даже при отсутствии его UI.
Побочные чтения успеха используют актуальный client этого owner.

Затронутый набор: **86/86, exit0**, пять файлов: panel-colony-shell-outcome,
panel-colony-review, panel-colony-parity, panel-game-bootstrap-parity,

## Точные границы

- Это guard живого экземпляра контроллера. Полный reload/новая вкладка/новый
  экземпляр приложения не обеспечивают сохранение unknown state.
- Серверная идемпотентность, дедупликация между вкладками и сверка статуса
  потерянной заявки не реализованы. Перезагрузка не является безопасным повтором.
- Самостоятельные транспортные повторы браузера при раннем обрыве соединения
  также не предотвращаются этим UI guard; клиентский request ID не доказывает
  серверную дедупликацию. Диагностика приложена, backend не менялся.
- Состояние не выводится из баланса или текущего снимка гражданина: они не
  доказывают исход конкретной заявки.
- Voting и остальные известные ограничения не менялись; это узкий Colony fix.
- Нового большого ZIP/27-частного upload до завершения re-review нет.
