# Core Engagement Features

**Status:** Design v0.1 (2026-05-02)
**Cope:** игронезависимые механики платформы для активного вовлечения зрителя.

Эти фичи работают **без активного модуля** (то есть на Free-tier и на любой игре стримера). Они формируют «третий столп» продукта помимо пассивной лояльности и игровой интеграции:

1. **Pasivная лояльность** — очки за просмотр, инвентарь, уровни, ачивки (есть)
2. **Игровая интеграция** — модули типа RimWorld (есть, формализуется в [MODULE_API.md](MODULE_API.md))
3. **Core engagement** — этот документ

См. также: [PLATFORM_VISION.md](../../PLATFORM_VISION.md) §видение, [MODULE_API.md §9.1](MODULE_API.md) — Core shop как часть game-agnostic слоя.

---

## Дизайн-принципы для всех трёх фич

1. **Не выглядит как казино.** Никаких слот-визуалов, mы-machine звуков, $-баннеров. Pie-charts и чистые UI.
2. **Цена/прайз чётко известны зрителю до участия.** Никакой dark-pattern «может быть выпадет, может быть нет».
3. **Точки уходят как настоящий sink.** Не zero-sum между зрителями (как казино RTP=92%), а реально съедаются ядром.
4. **Streamer-controlled.** Стример активирует/настраивает/закрывает каждый round.
5. **Не блокирует core (loyalty) на Free-tier.** Все три фичи доступны бесплатно.

## 1. Stream Director Vote ⭐

### Концепт
Зрители ставят очки на «что стример сделает дальше». После окна ставок крутится «барабан» (взвешенный по сумме ставок) — выпадает один вариант. Стример делает.

**Чем отличается от казино:** приз — **не очки/предметы**, а **действие стримера**. Приз нельзя сконвертировать в деньги. Это «стрим-pay-to-suggest» а не игра.

### Механика
1. Стример из admin-UI открывает round:
   - Тип: «free-form» (зрители вводят текст) ИЛИ «categories» (выбор из списка стримера)
   - Окно: 5 / 10 / 15 минут
   - Минимальная ставка: 100 / 500 / 1000💎
   - Cooldown между раундами: 30 / 60 / 120 минут
2. Зрители в extension'е:
   - Выбирают категорию или вводят предложение (если free-form)
   - Ставят сумму (любую кратную минимуму)
   - Своя ставка увеличивает «вес» этого предложения в барабане
   - Можно ставить на чужие предложения (если зашло)
3. По истечении таймера:
   - Анимация круга с секторами пропорциональными суммам ставок
   - Указатель крутится 5-10 сек, остаётся на одном предложении
   - Алерт на оверлее всем: «@username's choice WON: <text>»
4. Стример делает выбранное (или жмёт «отказаться» — тогда приз идёт топ-2 ставке).

### Модерация (для free-form)
Без неё виверы будут предлагать «покажи лицо» / «выпей пива» / прочие манипуляции.
- **Pre-categories** — стример заранее задаёт 4-8 категорий, виверы выбирают из списка. Самый безопасный режим.
- **Open submission with mod-approval** — вивер пишет предложение, стример/мод аппрувит за 60 сек. Иначе ставка возвращается. Сложнее, но гибче.
- **Self-curation** — только level 10+ виверы могут предлагать open-text. Уровень = доказательство «не тролль-однодневка».

### Экономика (sink)

Базовая модель — **partial-burn**:
- Победителю: 0% (награда — действие стримера)
- Топ-3 ставке проигравших: возврат 50% / 25% / 10% соответственно
- Остальные: 0% (точки сожжены)

**Пример:** 30 виверов поставили по 1000💎 = пул 30 000💎.
- Победитель: 0
- Топ-3: 500 + 250 + 100 = 850 (возврат)
- Сожжено: ~29 150💎 (97% sink)

**Альтернатива — pure-burn:** все ставки в никуда (100% sink). Гарантирует sink, но обижает casual-юзеров.

**Альтернатива — split-pool:** все стейки делятся между топ-N процентов с большей долей (50% sink приблизительно). Самый «дружелюбный».

Стример выбирает режим из admin-UI.

### UX заметки
- Visual: pie chart с секторами пропорциональными ставкам, не slot-machine
- Звук: гонг при крутке, не «джекпот»
- На overlay'e: после результата 5-секундный alert «@user's choice: <text>»
- Без слов «roulette» / «wheel of fortune» в UI

### Risk Twitch review
🟢 **Низкий.** Похоже на:
- Channel Points Predictions (Twitch own feature)
- Twitch Polls (Twitch own feature)
- StreamElements giveaway-раффлы

Главное — не называть «Roulette» в Extension Store description.

### Связь с существующим кодом
В `routes/event.py` уже есть `roulette` / `auction`. **Переиспользовать**:
- `EventManager.add_to_pool` → `Round.place_stake`
- `EventManager.start_event(type='roulette')` → `Round.start(type='director_vote')`
- Frontend `frontend/family.js` — переделать UI под pie-chart визуал

Переименовать в код: `roulette` → `director_vote`, `bid` → `stake`, `pool` → `total_stakes`.

## 2. Predictions

### Концепт
Стример создаёт прогноз (например «выживет ли пешка в следующем рейде?»). Зрители ставят очки на свой вариант. После закрытия — победившая сторона делит пул проигравших (минус house edge).

### Механика
1. Стример создаёт prediction в admin-UI:
   - Вопрос: text
   - Outcomes: 2-5 вариантов (Yes/No или multiple)
   - Окно ставок: 30 сек / 1 мин / 5 мин
   - Минимальная ставка: 100💎
   - Максимальная (опц.): для анти-whale
2. Зрители в extension'е:
   - Видят все варианты
   - Видят текущее распределение ставок (как в Twitch Predictions)
   - Ставят очки на один из вариантов
3. Стример закрывает window, потом маркирует winning outcome:
   - Можно автоматизировать (по signaling из мода — например «pawn умерла» triggers correct=No)
   - Или ручная маркировка
4. Распределение:
   - Из пула проигравших отнимается `house_edge` (10-20%, настраивается стримером)
   - Остаток делится между поставившими на winning outcome пропорционально их ставке
   - Каждый победитель получает: `own_winning_stake + (own_winning_stake / total_winning_stakes) × (losing_pool − house_edge)`

### Экономика (sink)

**House edge — настоящий sink.** На 10% house edge:
- Поставлено: 10 000💎 проигравшими + 5 000💎 победившими = 15 000💎
- House забирает: 10% × 10 000 = 1 000💎 (sink)
- Победители получают: 5 000 (своё) + 9 000 (доля проигравших)

В долгосрочке house edge гарантирует сжигание ~10-20% всего поставленного.

### UX заметки
- Похоже на нативный Twitch Predictions UI — двухколоночный с прогресс-баром
- Real-time update сумм по сторонам
- После закрытия — анимация «расчёт результатов»
- Сообщение в чат «🔮 @user угадал и забрал N💎»

### Risk Twitch review
🟢 **Очень низкий.** Это **прямой клон Twitch Predictions** — официальной фичи Twitch. У Twitch с этим проблем нет, у нас не должно быть.

Единственное условие — не называть «казино» / «гэмблинг» в описании.

### Идея интеграции с модулем
Когда модуль активен (например RimWorld), prediction может triggert'ться **автоматически из мода**:
- Мод detects: «пешка @user starts raid combat» → отправляет event `prediction.opportunity`
- Core создаёт prediction «выживет?» → зрители ставят
- Мод detects: «пешка died» → отправляет event `prediction.resolve(no)`
- Core закрывает prediction автоматом

Это **уникальная** фича связки core + module — Twitch Predictions так не умеет, потому что нет источника events.

## 3. Lootboxes (item-or-points)

### Концепт
Зритель платит N очков → открывает «сундук» → выпадает или **предмет из инвентаря**, или **очки** (с разной величиной).

**Без таймеров.** По требованию пользователя: только постоянные предметы и точки. Без расходников/buff'ов с истекающим эффектом.

### Механика
1. Стример настраивает в admin-UI несколько типов сундуков:
   - **Малый** — 100💎, выпадают распространённые предметы или очки 50-150💎
   - **Средний** — 500💎, common-uncommon items + очки 200-700💎
   - **Большой** — 2000💎, до epic items + очки 1000-3000💎
2. Каждый сундук имеет таблицу выпадений с **известными процентами**:
   ```
   Малый сундук (100💎):
     50%: 50💎  (потеря 50)
     20%: 100💎 (refund)
     15%: 150💎 (выигрыш 50)
     10%: Деревяшка (предмет)
     4%: Камень
     1%: Амулет
   ```
3. Зритель кликает «Открыть» → анимация → результат
4. Если выпал предмет — добавляется в inventory (постоянно)
5. Если очки — на баланс

### Экономика (sink)

**House edge закладывается в распределение.** Возьмём малый сундук:
- Стоимость: 100💎
- Ожидаемая отдача в очках: `0.5×50 + 0.2×100 + 0.15×150` = 25 + 20 + 22.5 = 67.5💎
- Ожидаемая отдача в предметах (intrinsic value): `0.10×1 + 0.04×6 + 0.01×32` = 0.1 + 0.24 + 0.32 = 0.66💎эквивалент
- Итого ожидаемая отдача: ~68💎
- **Sink:** 100 - 68 = **32💎 (32% house edge)**

Это **более жёсткий sink чем казино** (там было 8%). Намеренно — sink через лутбоксы должен быть значимым.

### UX заметки
- **Не slot-машина.** Анимация «открытия сундука»: коробка дрожит, открывается, выскакивает результат с подсветкой по rarity
- Звук: «открытие», не «kerching»
- **Прозрачная таблица drop rates** видна виверу до открытия (требование Twitch и здравого смысла)
- На оверлее: только редкие выпадения (epic+) показываются всем

### Risk Twitch review
🟧 **Средний.** Loot boxes сами по себе не запрещены (если виртуальная валюта + виртуальный приз без обмена на $$). Но:
- Есть страны с регуляцией (Belgium, Netherlands считают loot boxes гэмблингом)
- Twitch может flag'нуть в зависимости от настроения reviewer'а

**Mitigations:**
- **Опубликовать drop rates** прямо в UI (не прятать)
- В описании: «collectible chests with virtual items»
- Не использовать «pull» / «gacha» / «loot box» в названии — это триггер-слова. Использовать «treasure chest» / «mystery box» / «reward bag»

### Связь с существующим кодом
Текущий `routes/casino.py` `play_slots` — наполовину готовый каркас:
- Probability-weighted random pick → есть
- Списание ставки → есть
- Выдача награды → есть

Переписать визуал, заменить «слот-результат» на «сундук-открытие», поправить таблицу выпадений.

## Что **не** делаем (по решению пользователя)

- ❌ **Расходники с истекающим эффектом** (бусты на 2 часа, etc.) — отвергнуто. Только постоянные предметы или очки в loot boxes.
- ❌ **Storage rent** — отвергнуто (не звучит как «продукт за который платят», а как «штраф»).
- ❌ **Чат-команды для viewer'ов** (`!spin 100`) — отвергнуто из-за чат-спама.
- ❌ **Уход на сайт как primary surface** — extension остаётся главным интерфейсом, сайт = только для admin-UI.

## Что **под вопросом** (TBD)

- 🤔 **Дуэли с скрытым ходом** (RPS) — между виверами. Может быть flagged как «wagering between users». Решить:
  - Оставить и подать на review — посмотреть реакцию
  - Переделать в team battles (без личных ставок, командный leaderboard)
  - Заменить на skill-PvP (1v1 reaction game)
- 🤔 **Permanent upgrades / idle progression** — апгрейды +5% доход за фикс. цену. Sink-механика, но возможно слишком пассивная для extension'а. **Пока отложено.**

## Реализационные приоритеты

| Фича | Приоритет | Сложность | Когда делать |
|---|---|---:|---|
| Stream Director Vote | **Высокий** | 5-7 ч | После M3 (multi-tenant запросы) — переиспользует существующий `event.py` |
| Predictions | **Высокий** | 6-8 ч | После M3, можно параллельно с Director Vote |
| Lootboxes | Средний | 3-5 ч | После M3, переписывает существующий casino-код |
| Удалить старое казино (slots, double, bet) | Низкий | 1-2 ч | Когда лутбоксы готовы |

**Все три фичи можно сделать в рамках одной сессии M-extras (~15-20 ч)** после завершения M2-M6 multi-tenant.
