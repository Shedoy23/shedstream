# Покупка снаряжения без багажа — локально, 21.09.2026

Запрос владельца: новый зритель должен покупать вещи до создания собственного
клана. Принято: если багаж отсутствует, купить и надеть; при занятом слоте явно
подтвердить продажу старой вещи. Причина блокировки была в обязательном
PartyBelongedTo.ItemRoster на backend и в C#, а не в проверке Clan.

## Поведение

- Есть собственный доступный багаж: прежняя покупка в ItemRoster.
- Нет багажа, герой жив, свободен, игра вне Mission: выбрать слот и купить
  прямо в BattleEquipment. Герой без клана не требует искусственного клана/отряда.
- Для занятого слота показываются старая вещь, её стоимость продажи и итог.
  Продажа использует EquipmentElement.ItemValue, включая модификатор качества.
  Это внутренняя стоимость вещи, не рыночная котировка города и не цена магазина
  с его множителем x10. Стоимость покупки не менялась.
- Списывается разница с Hero.Gold. Если старая вещь дороже новой, остаток
  зачисляется; защита от переполнения баланса. Старую вещь не переносим в ledger.
- Подтверждение требуется и для пустого слота. В бою/сцене и плену покупка с
  надеванием запрещена. Снятие в багаж/прочие операции без багажа не открыты.
- Backend формирует варианты по слотам. Клиент подтверждает конкретные item,
  modifier, owned_id, цены. Они проверяются заново; мод повторно проверяет
  реальные слот/предмет/качество/цену, save, hero и session до списания.
- При смене наличия багажа между подтверждением и выполнением — отказ,
  без незаметной смены способа выдачи. При ошибке до commit восстанавливаются
  снаряжение и списание/зачисление. Успех отправляется после наблюдения эффекта.
- Старые моды без buy_equip_available продолжают запрещать покупку без багажа.
  Старый клиент без equip_now получает отказ с просьбой выбрать слот.
