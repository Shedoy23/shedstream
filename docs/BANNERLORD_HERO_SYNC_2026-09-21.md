## Наблюдение

В игровом логе 21.09 `module.heroes_snapshot` многократно отклонён с
`UNIQUE constraint failed: bannerlord_heroes.channel_id, bannerlord_heroes.hero_id`.
Игра видит AnalniyShekotyn (уровень 32, 797864 динара), но чтение боевой базы

Обработчик обновлял идентичности по username, пока старые строки продолжали
занимать hero_id. Коллизия отменяла восстановление всего списка. Снимки
инвентаря после этого не проходили проверку hero_id. ACK транспорта сам по себе
не доказывает сохранение inventory snapshot: обработчик может пропустить его.

## Исправление

- Полный список проверяется на неоднозначные имена/идентификаторы до записи.
- В одной BEGIN IMMEDIATE старые идентификаторы временно освобождаются,
  затем устанавливается список игры и удаляются отсутствующие записи по
  прежней политике. Уровень, золото и прочие поля существующего username
  сохраняются; герой из списка живых получает is_alive=1.
- Чужой save_id не заменяет текущий список. Ошибка записи откатывает всю
  операцию, включая временные идентификаторы. Каналы изолированы.
- Явный `build:null` из текущего снимка отличается от отсутствующего поля
  или пустого объекта. Для старого героя backend сообщает `legacy_build`;
  UI показывает серверную причину в Герое и Бою, экранируя текст.
- Старые герои не переводятся на новые сборки и ничего не получают заново:
  это сохраняет решение из BANNERLORD_FREE_BUILDS_2026-09-17.md.
