## Что исправлено относительно alpha.1

1. **Инструкция вела к недостижимой проверке.** `START-HERE.txt` предлагал
   сверить SHA-256 «по файлу `.sha256` рядом с ZIP», но этот файл лежит вне
   архива и при отправке одного ZIP до тестировщика не доезжает. Команды для
   проверки не было вовсе. Теперь хеш присылается отдельным сообщением, а в
   инструкции есть готовая команда `Get-FileHash`.
2. **SmartScreen был описан абстрактно.** Синее окно «Система Windows защитила
   ваш компьютер» прячет кнопку запуска за ссылкой «Подробнее». Тестировщик,
   который этого не знает, закрывает окно и сообщает «не запускается» — это
   самый дешёвый способ потерять первую установку и испортить TTTR. Оба клика
   теперь названы дословно.
3. **Метаданные могли лгать о происхождении.** `RELEASE.json` в alpha.1
   записал `source_commit`, не содержавший собранного кода, потому что сборка
   шла по грязному рабочему дереву. Упаковщик теперь отказывается собирать
   пакет при незакоммиченных изменениях.
4. **Кодировка инструкции ничем не защищалась.** `package-manager-alpha.ps1`
   не имел BOM, и оболочка, читающая его как ANSI, молча превратила бы русский
   текст в кракозябры уже внутри отдаваемого архива. Файл сохранён с BOM, а
   после записи `START-HERE.txt` проверяется канарейкой из кодов символов —
   она не искажается вместе с текстом и поэтому ловит подмену.

Первая версия канарейки была написана неверно: она искала латиницу диапазона
`0xC0–0xFF`, а искажение русского текста через cp1251 даёт кириллицу же
(`Подробнее` → `РџРѕРґСЂРѕР±РЅРµРµ`), и проверка молча пропускала бы брак.
Ошибка найдена прогоном на образце искажённого текста до того, как проверка
попала в пакет.

## Проверка

Каждый пункт выполнен на собранном архиве, а не на исходниках:

- SHA-256 архива совпал с содержимым `.zip.sha256`;
- содержимое архива — ровно четыре ожидаемых файла;
- архив распакован во временную папку вне repository и запущен оттуда: окно
  открылось, процесс отвечал, закрыт штатно, временная копия удалена;
- Product version внутри EXE содержит тот же commit, что и `RELEASE.json`;
- канарейка кодировки принимает корректный текст и отклоняет искажённый;
- Manager Core self-test: 70 проверок, **код возврата `0`**.

## Известное ограничение

EXE не подписан Authenticode — предупреждение Windows ожидаемо и описано в
инструкции. Clean Windows без dev tools остаётся отдельным M1 evidence: на
машине разработчика установлен .NET SDK, поэтому «работает без инструментов
разработчика» здесь принципиально недоказуемо.
