# Призывы не доходили до игры после сбоя стартового ping

21.09 после 14:15 заявки player.spawn (AnalniyShekotyn, slopkom, antitail,
dzirtdourden и другие) оставались queued, без dispatched_at. Игра при этом
передавала inventory/state events. В логе текущего запуска: 14:11:08.717
`ping ERROR: HttpRequestException`, затем `Backend connectivity: FAILED`;
`ActionPoller started` отсутствует. Игра дошла до боя, DET-STATS active=0.

Причина: BannerlordLinkModule запускал ActionPoller только после успешных
однократных ping И bootstrap-handshake. Любой временный сетевой сбой при
запуске навсегда отключал приём команд до перезапуска игры. Независимые
campaign-пуши восстанавливались, из-за чего UI показывал онлайн.

Исправлено: при наличии токена регистрация обработчиков и запуск ActionPoller
происходят до сетевого probe. Сам ActionPoller уже имеет цикл повторных
подключений. Начальный ping и bootstrap-handshake остаются диагностикой,
а не условием запуска приёма. Без токена poller не запускается.

Тест scripts/test-bannerlord-poller-startup.py компилирует настоящий блок
инициализации модуля с управляемым сетевым клиентом: зависший/неуспешный ping,
отказ handshake, отсутствие токена, регистрация до опроса. До исправления
exit 1; тест закоммичен ebfc2a7; после исправления exit 0. Release build:
0 предупреждений, 0 ошибок. Это ещё не подтверждение призыва в живой игре.

DLL подготовлена, НЕ установлена: игра запущена. Нужны закрытие игры и
лаунчера, резерв текущей DLL/PDB, установка и сверка хэшей, затем повтор
запуска с проверкой ActionPoller started и обработки player.spawn.
Боевые заявки/статусы/балансы вручную не менялись. Не нажимать призыв
повторно: заявки уже накоплены в серверной очереди.
