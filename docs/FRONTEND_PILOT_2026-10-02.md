# Фронт: надёжность, измерение спроса и React-пилот, 02.10.2026

Локальная кандидатная ветка `dot/frontend-reliability-react-pilot-20261002`, основа
`7e382b1ca648a2719206f5ba2bec680ca557ca4f`. Main и опубликованные ветки проверены
перед началом. `claude/map-data-export-20260930` новее по документации/карте,
но фронт совпадает. Полная отдельная копия репозитория, не аудиторская выборка.

Разрешение владельца: исправить найденные проблемы фронта, начать React-пилот
турнира и добавить недостающие счётчики для выбора частых/редких функций.
Только локальные коммиты. Публикации, PR, установки модов, обращения к реальной
БД, изменения production и замены отправленного Twitch-архива не было.

## Исправленные механизмы

1. Переименование вассала: loader защищал форму от polling, но Cancel,
   неизменённое имя и успешная отправка вызывали этот же loader, не закрывая
   форму. Теперь исходные DOM-узлы с их обработчиками возвращаются явно.
   `null`/`false`/`success:false` и исключения не считаются успехом; введённое
   имя остаётся, ошибка видна, повтор разрешён. Повторный submit блокируется.
2. Hero recovery: замена DOM при ошибке/отсутствии/смерти героя оставляла
   structural/HTML cache от прежнего экрана. Теперь заменённый DOM инвалидирует
   оба кэша. Запоздалый ответ не перекрашивает новую загрузку или остановленный
   модуль; delayed refresh после действия также связан с lifecycle.
3. Dynasty: успешный hero poll больше не запускает её HTTP-подзагрузки, когда
   выбран другой внутренний tab, скрыта внешняя вкладка интеграции или закрыта
   панель. При настоящем возвращении registry вызывает обновление видимого
   модуля; Dynasty загружает прежние summaries, включая свёрнутые секции. В тесте главы клана: 13 HTTP → 1 на
   hero poll при Combat (12 запросов Dynasty отложены до её открытия).
   Это измерение данного сценария, не заявление об ускорении всех модулей.
4. Обнаруженный независимым обзором край: JWT обновляется и при том же зрителе.
   Жизнь обработчика редактора не должна равняться жизни одного токена. Отдельно
   проверяются token refresh и смена идентичности; старый сетевой ответ не может
   применяться к новому контексту.

## UI-счётчики

Имеющийся `feature_usage` считает принятые Bannerlord-действия, `module_actions`
содержит состояния очереди/ACK. Они сохранены. Новые `ui_feature_usage` и
`ui_usage_batches` (M134.ui_usage) измеряют другие факты:

- `section_open`: переходы верхних tab, четырёх Bannerlord tab и раскрытие
  явно помеченных details/секций; рендер и восстановление сохранённого состояния
  сюда не попадают
- После каждого реального repaint привязка details выполняется внутри его
  DOM-поддерева, включая поздние async loaders; обновлённые данные и начальное
  open-состояние не считаются новым открытием
- `action_attempt`: вызов общего `ShedLink.buyAction` после локальной авторизации,
  перед проверкой повторного клика; отказ или duplicate guard не стирают попытку
- `panel_view`: наблюдение инструментированной панели для знаменателя охвата

Не записываются имена, текст, цели, цена, содержимое action payload, JWT или
браузерный постоянный идентификатор. Канал и существующий linked Twitch user_id
берутся из проверенного JWT. Эти клиентские утверждения не дают игровых прав.

Отдельный endpoint `POST /api/viewer/ui-usage`: allowlist, пределы тела/событий,
свой небольшой quota, одноатомарная дедупликация batch UUID и счётчиков.
Frontend отправляет небольшие пачки, не ждёт их перед действием и не меняет
его результат. Проблема статистики не блокирует покупку. Сохранение агрегатов
90 UTC дней, dedupe 24 часа; старое удаляется при следующей записи данного
канала. У неактивных каналов место больше не растёт.

Отчёт по ЯВНО выбранной копии БД, всегда read-only:

```sh
python scripts/ui-usage-report.py --db ./snapshot.db --channel CHANNEL_ID --days 14
```

`count` и `unique_viewers` различаются: один человек за много дней не становится
многими людьми. Отчёт отдельно даёт охват относительно наблюдавших эту игровую
панель при активном модуле. Принятые сервером действия и статусы ACK идут другим
набором, без ложной общей «конверсии» между разными клиентскими когортами.

Пределы: старый замороженный frontend этих событий не шлёт; прямые legacy/core
endpoint-вызовы в обход общего dispatcher ещё не инструментированы. Потери
возможны при закрытии страницы, смене токена и превышении маленьких queue caps.
Отсутствие строки не доказывает нулевой спрос. Значение active_module на момент
приёма не доказывает доступность конкретной кнопки или живую игру. Для решения
о скрытии функции смотреть охват, частоту и пригодность действия в контексте,
а не один абсолютный счётчик. Новая статистика начнёт поступать только после
отдельно разрешённых backend rollout и будущего frontend release.

## React + TypeScript

`frontend-next/` — отдельный Vite-проект. Подробные границы, DTO, архитектура и
команды находятся в [его README](../frontend-next/README.md). Текущий build
всегда fixture-only: HTTP action adapter в демонстрационный bundle не включён,
нет переключателя на настоящий EBS. В существующие Twitch shell он не встроен.

Пилот сохраняет серверный источник истины, отдельные transport/controller/view,
latest JWT и единственного владельца DOM. Очередь, участники, регистрация и
бесплатный прогноз используют существующие контракты. Взнос/награды/общий лимит
раундов не выдумываются. Принятый запрос не объявляется выполненным в игре.
React и JSX не исполняют строки сервера как HTML.

## Отдельно найдено, не исправляется скрыто

Прогнозы прежних турниров: M25 использует PK `(channel_id,bettor,round_index)`.
GET и проверка дубля в `routes/bannerlord.py` не учитывают `resolved/started_at`;
start в `_adapter.py` сбрасывает раунд без удаления прогнозов, end только
помечает resolved. Старый прогноз нулевого раунда способен показаться или
заблокировать новый турнир. Нужны отдельное воспроизведение и решение о
межтурнирной идентичности/совместимости; React не должен придумывать обход.
Ссылки: `migrations/m25_bannerlord_tournament_bets.py`, `bannerlord.py`
`bannerlord_tournament`/ветка `tournament.predict`, `_adapter.py`
`_on_tournament_started`/обработка завершения. Не выдавать UI-пилот за
исправление этого старого backend-контракта.
