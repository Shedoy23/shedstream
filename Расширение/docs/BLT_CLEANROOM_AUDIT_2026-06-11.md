# BLT clean-room audit — pass 1 (2026-06-11)

> **ROADMAP 1.4.** Это первый *построчный* (имена/числа/выражение кода) аудит на чистоту
> clean-room против BLT-референса. Прежние документы (`BLT_AUDIT_2026-05-28.md`,
> `BLT_AUDIT_HERO_LIFECYCLE.md`) сравнивали **фичи/flow**, а не выражение кода — это
> другой, и недостающий, слой. **Не юридическое заключение** — инженерный аудит; перед
> публичным релизом стоит финальная проверка юристом.

## Зачем это (the bar)

BLT («Bannerlord Tweaks» / Bannerlord-Twitch) — LGPL 2.1. Авторское право защищает
**выражение** (текст кода, структура), а не **идеи/факты/функциональные требования**.
- Можно: идеи, архитектурные паттерны, публичные API движка TaleWorlds, короткие идиомы.
- Нельзя: копировать тела методов/классов, структуру дословно, «один-в-один» имена+числа
  как компиляцию.
Цель 1.4 — доказуемо подтвердить, что `BannerlordLink` — оригинальное произведение
(которым владеет автор), а не производное под копилефтом, иначе публичный/Twitch-релиз
заблокирован.

## Методология этого прохода

1. **Инвентарь имён+чисел** обеих сторон (наш модуль / `reference/BLT_RC22/`), затем дифф.
2. **Сравнение выражения кода** на самом рискованном кластере (по 76 файлам, ссылающимся на
   BLT в комментариях, выбраны топ по риску). Рубрика:
   - **COPIED** — те же операторы в том же порядке, те же имена локальных переменных,
     идентичные числа/строки/комментарии. (Высокий риск.)
   - **STRUCTURAL** — похожая последовательность вызовов, но независимо выражено.
   - **API-ONLY** — совпадение только в вызовах движка TaleWorlds (неизбежно). Чисто.
   - **ORIGINAL** — нет значимого пересечения.

**Покрыто в этом проходе:** `AdoptHeroHandler`, `SummonHeroHandler`, `OneShotEffect`,
`AgentPfx`, `PowerVisualFx`, `PowersMissionBehavior` + полный инвентарь классов/способностей/
экономики. **Осталось (~70 файлов):** Tournament*, `KillRewardBehavior` (тело методов),
`DamageHookPatch` (формула AoE-затухания vs BLT), clan/kingdom/family/economy-хендлеры,
patches. См. «Continuation» внизу.

## Находки по выражению кода (топ-«близкие», все ≤ STRUCTURAL)

Ни одного дословного копирования. Ближайшие места (стоит развести для крепости clean-room):

1. **`SummonHeroHandler` — перенос ростера (`-1/+1`)** *(самое близкое в кодовой базе)*.
   Локальные переменные `wasLeader`, `oldHP`, `originalHeroParty` совпадают с BLT по имени и
   назначению; в комментарии процитирован дословный кусок BLT. → **Fix:** переименовать
   переменные, заменить дословную цитату BLT на пересказ (атрибуцию оставить).
2. **`SummonHeroHandler` — `AccessTools.Field(typeof(Agent), "_name")`**. Строковый литерал
   `"_name"` + `SetValue(agent, new TextObject(...))` совпадают, **но это единственный
   способ переименовать агента в TaleWorlds** (альтернативного API нет). → Defensible;
   задокументировать «нет альтернативы», не считать копией.
3. **`SummonHeroHandler` — петля `Expire()/SetSpawnIndex(0)`**. Структурно идентична (разнится
   лишь имя цикловой переменной). → **Fix:** обернуть в свой хелпер `InvalidateMissionCaches()`.
4. **`OneShotEffect` — звуковой блок** `MakeSound(..., false, true, idx, -1)`. Список
   аргументов идентичен BLT, но значения продиктованы API движка. → **Fix:** именованные
   комментарии к аргументам (`playInArea: false`, ...), чтобы показать осознанный выбор.
5. **`PowersMissionBehavior` — slow-tick аккумулятор** (`2.0f`, accumulate-and-compare).
   Совпадает константа и паттерн, **но сброс у нас `= 0f`, у BLT `-= interval`** — это уже
   различие. → Оставить наш сброс как есть (это и есть отличие); паттерн «копить dt и
   сравнивать» слишком общий, чтобы быть BLT-специфичным. LOW.

Всё остальное (создание героя, экипировка, выбор шаблона странника, спавн войск, fade-in,
mount-гарды, block-list миссий) — **API-ONLY или ORIGINAL**: совпадения форсированы
единственным доступным API движка, тела методов разные, свои гарды/логи/try-catch.

## Находки по числам

### ⚠️ Экономика убийств — `KillRewardBehavior.cs` (главный fix)
Наши константы = задокументированно «BLT defaults × 0.5», и ряд значений **идентичен** BLT:

| Наша константа | Наше значение | BLT default | Примечание |
|---|---|---|---|
| GOLD_PER_KILL | 2500 | 5000 | = ×0.5 |
| XP_PER_KILL | 2500 | 5000 | = ×0.5 |
| HEAL_PER_KILL | 10 | 20 | = ×0.5 |
| XP_PER_KILLED | 1000 | 2000 | = ×0.5 |
| RETINUE_GOLD_PER_KILL | 1250 | 2500 | = ×0.5 |
| WIN_GOLD / WIN_XP | 5000 | 10000 | = ×0.5 |
| RETINUE_DEATH_CHANCE | 0.025 | 0.025 | **идентично** |
| HORSE_FACTOR | 0.25 | 0.25 | **идентично** |
| LEVEL_SCALING_CAP | 5 | 5 | **идентично** |
| MINIMUM_GOLD_PER_KILL | 0.5 | 0.5 | **идентично** |

Отдельные числа — слабый объект авторского права, но **комментарии «× 0.5 от BLT defaults»
+ идентичные константы** — самое слабое место в истории «мы построили независимо».
**Remediation (2 уровня):**
- **(обязательно, безопасно)** убрать из кода все комментарии «× 0.5 от BLT defaults»,
  заменить на собственное обоснование баланса (наша валюта — крустики/динары 1:5, свои цели).
- **(сильнее, решение владельца)** переназначить значения от *своей* экономики, чтобы они
  перестали быть «BLT × 0.5» и идентичные совпадения ушли. **Меняет заработок зрителей** —
  продуктовое решение, не делать без подтверждения.

### Способности — точечно проверить в следующем проходе
- BLT `AreaOfEffectDef`: `DamageAtCenter` default **50**, `MaxAgentsToDamage` **4**, затухание
  `DamageAtCenter/(distance/Range+1)^2`. У нас explosive_arrows heavy_* = 50/80/120 (центр 50
  совпадает с дефолтом BLT). → сравнить **формулу затухания** в `DamageHookPatch` с BLT.
- Стоимости класса/экипировки и summon-cooldown — у BLT Tier1-6 5000..160000 / EquipHero
  25000..400000 / SummonCooldown 20s. Сверить наши.

заменяет юридическую проверку перед публичным релизом.
