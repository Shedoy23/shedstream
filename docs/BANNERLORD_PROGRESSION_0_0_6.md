# Прокачка Bannerlord — контракт локальной 0.0.6

Работа только в этой копии; не установка, не публикация. Остальные игры вне задачи.

## Согласованный срез

Игра публикует `progression` рядом с `build` в `hero.inventory_snapshot`.
Объекты движка читаются на main thread. Существующие save/session/hero/sequence
защищают полную замену снимка; backend M135 добавляет `progression_json`.

```json
{
  "version": 1,
  "skills": [{
    "id": "Mod.Skill", "level": 120, "focus": 2,
    "native_focus_limit": 7, "focus_limit": 5,
    "focus_options": [{"amount": 1, "cost_gold": 50000, "available": true, "reason": null}],
    "xp_available": true, "xp_reason": null
  }],
  "attributes": [{
    "id": "Mod.Attribute", "value": 4, "native_limit": 10, "limit": 10,
    "options": [{"amount": 1, "cost_gold": 50000, "available": true, "reason": null}]
  }],
  "random_xp_available": true, "random_xp_reason": null
}
```

Для начала UI покупает одно очко фокуса/атрибута за раз, как сейчас.
Текущий мод публикует только +1. Контракт допускает options для нескольких количеств; backend выбирает точный
option, не рассчитывает тариф или максимум самостоятельно. Нужен недоступный
option на +1 с причиной, даже если достигнут предел.

Цена фокуса 30/40/50/60/75 тысяч, атрибут 50 тысяч, предел покупки фокуса 5,
атрибута 10 и лимит покупки XP 330
пока остаются существующей политикой мода. Новые тарифы не изобретаются.
Игровые ограничения читаются из CharacterDevelopmentModel; ограничение продажи
отличается от native limit. Этот этап переносит решения и устраняет расхождение
между показом и исполнением, а не меняет баланс.

`GET /api/bannerlord/progression` требует viewer JWT:
`{success, ready, reason, message, context, progression, xp_offers}`.
`context = {save_id, equipment_session_id, hero_id}`.
Backend добавляет человеческие `reason_text` к options/XP и предложения XP
`{id, crusticov, xp, available, reason, reason_text}` из своей экономики.
Крустики и роль/скидка остаются на backend; игра определяет возможность получить XP.
Если показывается эффективная цена со скидкой, она идёт отдельным `price`,
а `crusticov` остаётся идентификатором исходного пресета.

UI отправляет существующее действие и параметры, но дополнительно
`progression_context` из показанного снимка. Для focus/attribute также
`expected_cost_gold` и `expected_value` (focus или значение атрибута).
Для XP обязательны `price: crusticov` и `expected_platform_price` из `price`
предложения. Никаких формул цен/лимитов/XP-пресетов в новом UI.

Backend выбирает известный опубликованный option и проверяет контекст/ожидаемую
цену/значение до оплаты и повторно внутри транзакции очереди. Подставленные
клиентом identity/cost/служебные поля не становятся авторитетными.
Без персонального снимка новые платные пути недоступны, а значения героя видны.
Снимок не использует strict inventory_seq как quote: он меняется от чужих полей.
Действие получает backend-owned save/session/hero, expected_cost_gold/value.
Мод повторно вычисляет то же предложение непосредственно перед списанием.
Цена или значение изменились — отказ, без неожиданной суммы/количества.

Ежедневный внутренний XP, текущий reward_boost и refund/idempotency сохраняются.
Легаси `player.modify_attribute` остаётся закрытым. После действия игра публикует
обновлённый снимок. Отказ и успех должны отражать наблюдаемый результат движка.

## Проверка

Пройдены backend-тесты нового контракта, оплаты, идемпотентности, возвратов,
снимков, оборудования, каталогов и защиты старых путей. Проверка реального
HTTP endpoint/SQLite: стример покупает пресет 500 за 250 крустиков; повтор
запроса не списывает повторно; дублированный отказ возвращает ровно 250.

Frontend: 14 проверок progression и 14 runtime-каталогов, общие проверки
buyAction/блокировки/загрузки. C#: ProgressionHarness 48, EquipmentShop 48,
NativeInventory 21, Build 79; Release-сборка без ошибок и предупреждений.
Это проверки с заглушками движка, не доказательство поведения живой кампании.

Старые frontend/mod не поддерживают новый обязательный контекст платной
прокачки. Frozen-client harness проходит, но не доказывает совместимость этих
трёх действий. Легаси config-поля сохранены только для совместимости остальных
путей. Новых campaign save-типов нет; backend требует миграцию M135.

Если после мутации невозможно прочитать результат, возвращается явная ошибка
подтверждения. При неизвестном результате фокуса/атрибута автоматического
возврата игровых динаров нет. Для XP сохраняется платформенный возврат;
редкий риск частично выданного XP при нечитаемом результате требует отдельного
протокола восстановления (см. DEFERRED.md).

Живая проверка пока невозможна без отдельной установки: локальная DLL отличается
от установленной, работающего процесса Bannerlord при начале задачи не обнаружено.
Ничего не устанавливалось и не публиковалось; Twitch ZIP 0.0.5 не изменён.
