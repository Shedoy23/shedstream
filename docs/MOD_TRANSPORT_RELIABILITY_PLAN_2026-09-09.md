# Пункт 1 — разбор до правки

Перепроверено по актуальному коду (не по прошлому отчёту).

**1.1. Хэш пишется в кэш ДО отправки.** `HeroStateSync.PushIfChanged`
(`BannerlordLink/src/Util/HeroStateSync.cs:52-65`):

```csharp
if (hashCache != null) hashCache[username] = hash;   // ← записали
PostStateUpdate(username, json);                     // ← только теперь шлём
return true;
```

Отправка не удалась — кэш уже утверждает, что этот снимок доставлен. Пока
состояние героя не изменится снова, `PushIfChanged` будет возвращать false, и
актуальный снимок НЕ уйдёт. Зритель видит замороженные золото/уровень/навыки.

**1.2. Результат отправки не используется вовсе.** `PostStateUpdate`
(`:67-84`) — `Task.Run` без возврата: `await PostEventAsync(...)` вызывается,
но его `bool` отбрасывается. Ошибка попадает только в лог.

**1.3. Успех определяется неверно даже там, где его смотрят.**
`BackendClient.PostEventAsync` (`BannerlordLink/src/Net/BackendClient.cs:218-221`):

```csharp
bool ok = response.Contains("\"status\":\"ok\"") || response.Contains("\"status\": \"ok\"");
```

А бэкенд (`Расширение/backend/routes/module_api.py:413`) возвращает
`{"status": "ok", "acks": [...]}` ВСЕГДА, и отказ отдельного конверта лежит
внутри: `{"id": ..., "success": false, "error": "event_not_in_manifest"}` либо
`"error": "<Тип исключения>: ..."` при падении обработчика. То есть
отклонённое событие мод считает подтверждённым. Это ровно тот случай, о
котором предупреждает задание: HTTP 200 и общий `status=ok` недостаточны.

**1.4. Нет защиты от обгона.** Отправки идут через `Task.Run` без
упорядочивания; при двух параллельных подтверждение старой могло бы затереть
состояние более новой (после того, как подтверждение вообще начнут учитывать).

**1.5. Загрузка сейва чистит кэш, но не отменяет старые отправки.**
`MainCampaignBehavior.ResyncAdoptedHeroes` (`:715-718`) делает
`_heroStateHashes.Clear()`. Сейчас это безвредно (кэш пишется синхронно), но
как только подтверждение станет асинхронным, callback от ОТМЕНЁННОЙ сессии
сможет записать хэш в кэш новой — и снимок нового сейва не уйдёт.

**Вывод.** Все пять требований задания к пункту 1 обоснованы актуальным кодом.
Правка должна быть точечной: подтверждение по конкретному конверту, кэш только
после подтверждения, поколение отправок против обгона, эпоха против старых
callback'ов, и никакого обращения к объектам движка из фонового потока (JSON
строится на главном потоке уже сейчас — это свойство сохранить).
