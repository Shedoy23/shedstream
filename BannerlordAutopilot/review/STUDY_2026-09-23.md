# Автопилот: обзор по коду, документам и логам 21–22.09 (23.09.2026)

Сделано по просьбе владельца «изучи наш мод автопилот». Источники: `README.md`,
`HANDOFF.md`, `review/*`, код `src/` (~7200 строк), тесты `tests/`, логи
`Документы\Mount and Blade II Bannerlord\Logs\autopilot_2026092{1,2}.txt`
(лог автопилота лежит в `Logs\`, НЕ в `Configs\ModLogs\`).

## Как устроен

- Раз в игровой час берёт решение ШТАТНОГО ИИ игры для партии игрока
  (`AiHourlyTick`, максимум оценок) и в режиме F11 применяет его
  (`SetPartyAiAction`). Свою стратегию не считает — кроме осад/обороны/сбора
  бандитов, где цель ищет сам.
- Каждые 0,5 с реального времени опрос состояния (`AutopilotSubModule.
  OnApplicationTick` → `PollState` / в бою `WatchMission`, `PollDialogs`,
  `PollDeployment`, `PollCompletedBattle`): поселение, встреча, бой, меню.
- Управление: F10 наблюдение, F11 применять, F12 выключить. Любой сбой, который
  код поймал, → `Disable(причина)` с записью `ВЫКЛЮЧЕНИЕ:` в логе.
- При запуске сверяет 494 ожидания к API игры (`EngineContract`); не сошлось —
  не включается.
- С BannerlordLink по коду не связан (отдельные сборки).

## Находки

1. **ТОЧНО: опрос раз в 0,5 с не обёрнут в перехват ошибок.** В
   `OnApplicationTick` → `PollState` (`AutopilotBehavior.cs:501`) и в бою
   `OnMissionTick` → `GiveControlToAi`/`RestorePlayerControl`
   (`BattleAutopilotMission.cs:46–58, 157, 299`) нет общего `try/catch`.
   Внутри `PollState` зовутся `PollArmy`, `PollEmergencyDefense` и др., у части
   из них своего перехвата нет (`AutopilotConquest.cs:87–154`,
   `AutopilotDefense.cs:53–106`). Любое исключение там = вылет игры вместо
   «автопилот выключился с причиной». Остальные пути (обслуживание, решения
   королевства, события, выход из поселения, часовой тик) перехвачены.
   Какой именно вызов бросит — ВЕРОЯТНО, не доказано: в логах 21–22.09 таких
   падений нет. Починка — одна обёртка на уровне опроса.
2. **ТОЧНО: автопилот сам выключался посреди эфира 7 раз.** 21.09 — пять раз
   `улучшение бойца не подтверждено` (проверка после апгрейда не увидела
   результата; ВЕРОЯТНО гонка с подтверждением), 22.09 — дважды
   `пункт «…» недоступен: У вас недостаточно людей!`. Каждый раз стример должен
   заметить и нажать F11. Остальные 19–20 выключений — F12 стримера.
3. **ТОЧНО: ни один из 7 проектов тестов автопилота не запускается в CI**
   (`.github/workflows/ci.yml`), только руками по README. Тесты — на заглушках
   движка, кроме `ContractCheck` (сверяет форму API с настоящими DLL).
   `ContractBlindSpots/ContractGetter/ContractScoresGetter` по HANDOFF 16.09 не
   компилируются из-за устаревших заглушек.
4. **Шум лога, не поломка.** 8515 строк за 22.09 «та же цель продолжается,
   приказ не перевыдаю» — это запись каждого пересчёта. Агент принял их за
   «метание цели»; проверка показала обратное: в худшем сеансе (14:29–15:45)
   155 смен цели и 124 прибытия — он доезжает до 80% целей, это объезд
   поселений ради набора/продажи. Оценка «1.000» — потолок штатной формулы.
5. **Итог боя не пишется** (`результат определён игрой`) — победы/поражения
   по логу не посчитать.
6. Вылеты 22.09: 09:46 — движок в `incident_hammer_of_the_sun`, вызванный
   темпом автопилота (разбор `ALLY_THANKS_AND_INCIDENT_2026-09-22.md`); 12:09 и
   13:10 — голосование о мире (см. `docs/BANNERLORD_CRASH_2026-09-22.md`); в
   логе автопилота исключений перед ними нет.

## Проверено вживую / только стендом (по HANDOFF)

Вживую: выбор цели и движение, обслуживание в поселении, осада и её
продолжение после боя с подмогой. Только стендом: полевой бой под ИИ, апгрейды,
экипировка, разгрузка, рейды, сбор бандитов, оборона феодов, армия, камеры,
RBM-интеграция. По логам 21–22.09 апгрейды, продажа, набор и бои фактически
работают.
